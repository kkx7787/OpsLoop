# 재가동 전 필수 코드 보완 (#130)

2026-10-18. 기반 `dc05894d`, 브랜치 `fix/130-restart-safety`. 운영 환경을 재가동하지 않고 코드와 격리 시험으로 검증한 범위다. 서비스 재개 승인이나 실환경 시험 완료를 뜻하지 않는다.

판정·차단 순서, 기존 연결 유지, 후속 차단 승인 범위, R006의 의미, SSM 권한 정책은 바꾸지 않았다. 특히 L4 교차 흡수 동시성, L16 리플레이, L28·L31 관문 장애 시험은 완료로 처리하지 않는다.

철회 기록의 만료 후 정리는 다음 로그아웃 때 수행한다. 별도 주기 작업을 추가하지 않았다.

## 적용 순서와 호환성

1. 실제 재구축을 승인한 다음에만 실행한다. 과거 DB를 재사용하면 기존 #129 마이그레이션까지 적용하고 백업한다.
2. 콘솔 A/B의 쓰기를 멈추고 DB 소유자로 `infra/migrations/20261018_restart_safety.sql`을 적용한다. 새 DB는 현재 `infra/schema.sql`을 사용한다. 트랜잭션·5초 잠금 제한이 있으며 반복 적용은 기존 철회·차단 결과를 지우지 않는다.
3. 모든 콘솔을 같은 코드로 교체한다. 옛 콘솔은 철회 기록을 검사하지 않으므로 혼용하지 않는다. 최초 재가동·백업 복원 시 **A/B에 동일한 새 SESSION_SECRET**을 배포해 옛 쿠키를 모두 무효화한다. 백업 이후의 로그아웃 기록은 옛 덤프에 없을 수 있다.
4. 수집 설치 묶음에 `puller/run_lock.py`를 포함한다(`puller/install-ingest.sh`가 폴더 전체를 복사). 수동 적재도 같은 코드·같은 OPSLOOP_HOME으로 실행한다. 잠금 파일을 실행 중 지우지 않는다. 백업 스크립트 사본은 `install-backup-agent.sh`로 갱신한다.
5. 집행기는 `OPSLOOP_BUCKET`, `OPSLOOP_GATEWAY_ID`, `OPSLOOP_BUCKET_OWNER`(버킷 소유 계정 12자리)를 명시한다. 기존 `/etc/default/opsloop-enforcer`의 값 변경은 파일부터 수행한다. AI 설치는 `OPSLOOP_AI_HOST`, `OPSLOOP_AI_SSH_USER`를 명시하며 기존 설정은 보존한다. 설정 누락 시 옛 환경으로 연결하지 않고 중단한다.
6. 기본 VM은 아직 개별 노드로 구성하지 않은 깨끗한 템플릿을 사용한다. `configure.sh`·`add-node.sh`는 대화형 터미널에서 실행하고 vmrun의 비밀번호 요청에 직접 입력한다. 환경변수로 비밀번호를 전달하지 않는다. seed에는 암호 해시가 있으므로 비밀 자료처럼 보관하고 불필요해지면 안전하게 제거한다.
7. 로그아웃 재사용 거부·다른 세션 유지·권한 검사·차단 요청/해제·백업/복원·복제본 식별자를 실제 환경에서 확인한다. 실패하면 운영을 열지 않는다. 세션 확인·로그아웃의 DB 오류는 503이며 성공으로 숨기지 않는다.

## 검증

기존 Python 3.12 / PostgreSQL 16 시험 이미지로 내부 전용 Docker 네트워크와 tmpfs DB를 사용했다. 외부 공개 포트, 운영 DB, AWS 호출, VMware 기동, 실제 GPU 호출은 없다. macOS 시험은 SSH·백업 대상·알림 등을 가짜 명령으로 바꿨다.

최종 결과와 소스·원문 로그 해시는 같은 폴더의 검증 기록을 따른다. 원문 로그는 개인 작업 폴더 `output/restart-safety-20261018/`에 보존한다. 시험 수에는 skip이 포함되므로 통과 수와 구분한다.

- 실제 DB: 로그아웃 쿠키 HTTP 재사용 거부·웹소켓 검증·다른 DB 풀에서의 철회·다른 세션 유지·철회 실패 503·반복 로그아웃·철회 권한·마이그레이션 재적용.
- 실제 제한 DB 역할: 콘솔의 결과 세 열 INSERT/UPDATE 거부, 집행기 적용·콘솔 연장/해제 허용, 결과 보존, 복원 카탈로그 일치.
- 실제 두 프로세스: 풀러/적재 중복 거부, 상속 fd, 다른 파일 fd 거부, 부모 종료 뒤 하위 프로세스 잠금 유지, 종료 후 재실행.
- 가짜 외부 명령: 비밀번호·해시가 인자/추적 출력에 없음, seed 0600, 백업 잠금 실패 시 원격 명령 0건, Cowrie 태그 거부, 설치 대상 누락 거부.
- 실제 botocore + Stubber: GetObject/PutObject에 소유자 조건 포함, 403 전파. AWS에서 실제 권한을 시험한 결과는 아님.
- 실제 `pg_dump`·`pg_restore`: 합성 자료의 철회 기록·집행 증거가 복원 뒤 같고, 복원된 콘솔 역할의 삭제·집행 결과 위조가 거부되는지 확인. 운영 복원 훈련은 아님.
- Terraform fmt/validate, Bash 문법·ShellCheck, diff 공백 검사.

## 실패를 거쳐 바로잡은 것

- 관문 기본값 제거 뒤 옛 ID를 자동 사용한다고 기대하던 시험을 명시적 시험 설정으로 변경했다.
- 새 철회 표·함수·보호 트리거에 맞춰 복원 도구와 카탈로그 기대값을 함께 수정했다. 옛 콘솔의 집행 증거 초기화를 허용하던 시험도 현재 계약대로 거부를 확인하도록 바꿨다.
- 첫 macOS 백업 전체 시험은 샌드박스 안에서 가짜 알림/신호 검사가 실패했다. 같은 코드를 샌드박스 밖에서 가짜 명령으로 재실행해 29개 모두 통과했다. 시험 대기 시간을 늘려 숨기지 않았다.
- API 전체 시험의 기존 ResourceWarning은 남아 있다. 경고 0이나 실환경 전체 통과로 표현하지 않는다.
