## 문제

- 사건 목록·상세의 담당 배정이 실제 판정자 확인과 섞여 혼동됐다. 대시보드 '내 담당 미판정'은 담당이 없는 사건을 가렸다.
- 주목 CVE의 '미확인'과 오래된 자산 정보가 사람의 판정 대기처럼 보였다.
- 자산 조사가 실패하면 다음 날 05:10까지 복구되지 않았고, AWS 인증이 만료되면 두 자산이 조용히 빠졌다.
- web-02 수집 허용 줄이 실행 중 설정에만 있어 방화벽 재적용·재부팅 뒤 수집이 끊겼다.
- 집행기 시험 일부가 판정 버전 확인(#105) 전 호출 방식이었다.

## 변경

- 판정: 목록에 최신 판정과 같은 기록의 판정자·저장 시각(`verdict_operator` · `verdict_at`)을 표시. 담당 배정 화면·담당 필터 제거, 옛 `assignment` 주소 조건은 무시. 대시보드는 '전체 미판정'으로 연결. 배정 API·열·이력과 동시 저장 충돌 방지(`expected_version`)는 유지
- 자산·CVE: '자산 해당 여부'로 용어 정리, 미확인 수·자동 대조 설명, 48시간 넘은 자산 경고, 최근 시도·대조 시각 표시
- 규칙 화면: 판정 → 집계 → 후보·리플레이 → 승격 절차와 자동 변경이 아님을 설명
- 자산 조사 실행기(`assets-schedule.py`): 로그인 때·15분마다 확인, 매일 05:10 기준, 일부 실패 4시간·적재 실패 15분 뒤 재시도, 파일 잠금, 20분 제한, 적재 전 data01 시계 확인. AWS 인증 실패는 자산별 실패로 기록하고 옛 성공 결과 보존
- web-02: `nftables.conf`의 `LOG_SENDERS`(web-01 · web-02), Ansible 인벤토리, 자산 조사 대상에 추가
- 문서: README · 내부망 README · 화면 설계 · 사건 담당 · 최종 개발 동결 문서 갱신. 10/03 측정값은 바꾸지 않음
