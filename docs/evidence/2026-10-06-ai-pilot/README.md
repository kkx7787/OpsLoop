# AI 판정 추천 시험 (2026-10-06)

판정은 사람이 한다. AI 는 사건 근거를 읽고 판정 후보, 한국어 근거 세 줄, 차단 제안을 추천만 한다.
이 폴더는 추천이 사람 판정과 얼마나 맞는지 잰 원자료다.

## 환경

- 모델 `gpt-oss:20b`, Ollama 0.35.1, 학교 GPU 서버 `gx10-482b`(NVIDIA GB10, 공용) 의 내 계정 rootless Docker 컨테이너
- 서버 포트는 `127.0.0.1:21434` 에만 열고 Mac 에서 SSH 터널(`ssh -N -L 21434:127.0.0.1:21434`)로 접근
- 공용 서버라 한 건씩 보내고, 모델은 5분 뒤(마지막 건은 즉시) 내린다. 생각 강도 low, temperature 0, seed 7, 문맥 8192, 출력 상한 700

## 데이터

- 대상: 사람 판정(`operator` han, ubuntu) 261건 중 시험 출발지를 뺀 253건. 판정 1,039건 중 778건은
  `system:v3-cutover` 가 "판정하지 않음"(undetermined)으로 일괄 기록한 것이라 대상이 아니다
- 근거는 `detector/triage.py gather()` 가 사람에게 보여 주는 것과 같은 범위(로그인, 명령, 파일, 웹 요청, 같은 구간 상위 사건)를
  읽기 전용 SQL 로 꺼냈다. 판정 뒤에 생기는 정보(지금 차단 상태, 그 뒤 사건)는 넣지 않았다
- 같은 페이로드 24시간 중복은 규칙이 흡수하지 않던 v1, v2 사건에만 계산한다(v3 는 규칙이 흡수)
- 정답(`label`)과 규칙 기반 제안(`proposed`)은 채점에만 쓰고 지시문에 넣지 않는다
- p3 부터 근거에 비밀번호 원문을 넣지 않는다(아래 'p3: 비밀번호를 뺀 다시 평가'). p1 · p2 파일도 커밋 전에 비밀번호 칸을 지웠다

## 원칙 (판정 기준 문서 §6 과 같게)

- 추천값은 threat, non_actionable, undetermined 셋뿐. 오탐과 양성 정탐은 사람만 판정한다
- 코드 안전장치: SSH 규칙(R001~R006) 밖 사건, 내부(사설) 출발지, 미결 추천에는 무조건 "사람 확인 필요"를 붙이고,
  위협이 아니면 차단 제안을 0 으로 만든다
- `<자료>` 안의 문장은 공격자가 만든 것일 수 있어 지시가 아니라 증거로만 읽게 한다
- 근거 줄이 망가지면(반복 생성) 씨앗을 바꿔 한 번 다시 묻는다

## 채점

- threat, non_actionable 사건: 같은 값을 추천하면 맞음, undetermined 는 보류, 다른 값은 틀림
- 오탐, 양성 정탐 사건: 위협을 추천하지 않고 사람 확인을 표시하면 맞음

## p3: 비밀번호를 뺀 다시 평가 (같은 100건)

p2 근거에는 공격자가 시도한 비밀번호 원문이 있었고, 결과 140건(조정 40 · 평가 100) 중 51건의 근거 문장에 비밀번호가 옮겨 적혔다.
콘솔은 타인의 실제 자격증명일 수 있어 비밀번호 원문을 화면에 내지 않는다(`app/main.py` raw). 그대로 운영하면 AI 추천 칸으로 새어
나간다. 그래서 근거에서 비밀번호를 빼고(계정 · 성공 여부 · 횟수만) 지시문은 그대로 둔 p3 로 같은 100건을 다시 돌렸다.
