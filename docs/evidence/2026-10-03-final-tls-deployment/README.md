# 최종 개발 판의 실제 HTTPS 배포와 회귀 확인

2026-10-03, 사용자 소유 VMware 시험 환경. 운영 URL은 `https://192.168.70.254:8443/`이다. 앱 소스는 `38720bd4fc0a4511dde91de96f5dff62bed5d12f`, A/B 실행 이미지는 `sha256:6fe67c018d9ac8cfb7bf81512bf7db28d0eb37d3cefe9272682e0d9d81489cbf`다. #113의 합류·Mac 감시 도구 수정은 `bc63c7e`이며 앱 이미지를 바꾸지 않았다.

이 기록은 이전 HTTP 판의 시험을 대체하지 않는 후속 회차다. 같은 Mac의 가상 머신과 로컬 Docker를 함께 사용했다. 물리 호스트 장애나 상시 운영 가용성을 검증한 결과가 아니다.

## 배포와 되돌리기

- 배포 꾸러미는 195개 파일, 1,445,175바이트다. SHA256은 `9e793393c0f39d51e15722c30fb1ae070836e660d58e81740ec94ff6e956bef4`다. `manifest.json`·`verification.json`에 내용과 대조 결과를 보존한다. 꾸러미 자체와 개인키는 이 폴더에 넣지 않았다.
- 기존 앱·이미지·compose·환경 파일·HAProxy 설정을 각 호스트의 비공개 백업에 보존했다. 배포 전 DB 백업은 26개 표, 새 마이그레이션 뒤 백업은 28개 표다. 둘 다 역할 8개와 주요 건수를 대조했다. **변경 작업 중 수동 실행한 백업이며 정기 예약 회차 성공의 증거는 아니다.**
- 첫 전환은 HAProxy reload 직후 master 소켓 연결 거절로 중단했다. 준비한 이전 앱/설정으로 복구한 뒤, 서비스 active와 소켓 응답을 기다리는 제한된 확인 절차를 추가했다. 두 번째 전환은 18:14:00 시작, 18:14:04 외부 HTTPS 200을 확인했다. 이는 배포 기록이며 무중단 전환 시간 측정은 아니다.
- 브라우저 → HAProxy → 콘솔 A/B를 TLS로 보호한다. DB·Loki·수집 경로 전체를 암호화한 것은 아니다. CA 개인키는 Mac에만 두고, B에는 B 전용 서버 인증서를 설치했다.
- 사용자 Mac에 CA 신뢰를 등록했다. 공개 CA 지문은 `EC:CD:9F:DC:63:89:29:AC:FC:AC:BB:AB:9F:4E:DC:A4:4F:60:F0:55:94:01:41:40:DF:16:CB:41:CA:68:06:B8`이다. 서버 인증서는 2027-01-01 15:39:42 KST 만료이며 21일 전 수동 갱신이 필요하다. 다른 허용 기기는 별도 신뢰 등록이 필요하다.

## 배포 중 발견한 운영 도구 결함

1. 방화벽 인증서 폴더가 root:0700이라 일반 사용자 curl이 공개 CA도 읽지 못했다. #113은 기존 sudo 권한으로 읽는 검사로 고쳤다. 폴더·개인키 권한을 넓히지 않았다. 합류 시험 23개 중 22개 통과, 실제 DB 환경이 필요한 1개는 건너뜀이다. 실제 VM 합류·DB 역할 검사는 별도로 통과했다.
2. Mac 감시 재설치에서 launchd bootstrap 오류 5가 한 번 발생했다. 원인은 확정하지 않았다. 오류 5에만 최대 3회 재시도하며 각 실패를 보이고, 다른 오류나 지속 실패는 실패로 종료한다. 감시 시험 60개를 통과했고 실제 설치에도 성공했다.
3. 최종 대조에서 data01 CLI 판정 파일이 옛 판으로 남아 있음을 발견했다(#115). 웹의 새 이미지와 CLI 설치는 별개였다. `/var/backups/opsloop/final-38720bd-cli/triage.py.before`에 기존 파일을 보존한 뒤 검증한 `38720bd`의 `triage.py`만 원자적으로 교체했다. SHA256 `dc0e2dc7…` → `a335d78a…`, 실제 콘솔 역할의 읽기 전용 버전 조회와 버전 누락 거절을 확인했다(`triage-install.log`). 수집·탐지·규칙 파일을 교체하거나 운영 판정을 제출하지 않았다. 재설치는 이 단일 회차용 도구를 그대로 반복하지 말고 새 소스 해시와 백업 경로를 확인해야 한다.

원문 실패 로그도 남겼다. B VM의 첫 nogui 부팅이 유지되지 않은 사례는 원인 미확정이며 이후 VMware 앱에서 부팅했다. 격리 복원 DB의 분리된 SSH 터널이 종료되어 첫 로그인에 503이 났고, 유지되는 실행 세션으로 터널을 다시 연 뒤 사용자 재로그인과 판정 저장을 확인했다. 이 현상만으로 제품 로그인 결함이나 특정 종료 원인을 단정하지 않는다.

## 측정 기록의 해석

장애 전환은 같은 300초 절차로 컨테이너 정지 3회와 강제 종료 3회를 구분한다. VM 전원 차단은 이번 회차에 포함하지 않는다. HTTP는 health·me 각 초당 10개, WSS는 브라우저 방식 4개와 네트워크 방식 4개다.

기존 계측기의 `failover_s`는 다른 콘솔이 20회 연속 성공한 묶음의 **첫 요청을 보낸 시각**이다. 20번째 응답을 확인한 시각은 `failover.*.confirmed_s`다. `switchover_s`는 장애 감지와 마지막 실패 끝 중 늦은 쪽이며 기존 합격선은 30초 이하다. 이 세 값을 같은 '완료 시간'으로 부르지 않는다. WSS 연결은 끊어지고 재연결될 수 있으므로 401이 없다는 것을 연결 단절 0으로 표현하지 않는다.

격리 복원은 마이그레이션 후 새 백업을 사용한다. 최신 30분을 대조에서 빼고 백업 이후 최소 15분을 포함하는 기존 절차를 유지하므로, 이번 새 백업 직후 시작한 회차에는 대조 창이 생길 때까지 기다린 시간이 들어간다. RTO에는 실제 경과를 그대로 남기며 과거 회차와 자동 복원 속도로 직접 비교하지 않는다.

복원 콘솔은 루프백 HTTP의 격리 환경이다. 새 앱과 새 DB 백업으로 서비스 사용을 확인했으며 CA·HAProxy·전체 VM을 새로 만들어 복원한 시험은 아니다.

## 남은 운영 조건

- Loki 보존 7일·30일 후보는 설정 검사만 했다. 기간 확정과 삭제 승인이 없어 운영 원본을 삭제하지 않았다.
- 백업·진입점 감시가 같은 Mac에 의존한다. 시작 전 잠자기·전원 꺼짐을 실행 중 caffeinate가 해결하지는 않는다. 새 판의 정기 백업 간격 개선은 관찰 전이다.
- 실제 외부 Teams 수신, 이번 판의 VM 전원 차단, 이미 맺어진 연결 종료는 미시험이다.
- 화면 검증은 선택한 업무·폭의 회귀 확인이다. 전체 접근성 인증이나 실제 다수 관제자의 효과 비교 실험이 아니다.

## 복원과 최종 정리

새 백업 격리 복원은 RTO 2579.524초, 서비스 재개 548.713초, 설계 RPO 187.097초다. 대조 창 대기·터널 복구·사람 확인을 포함한다. 원장 이벤트·세션·노드 지표 대조와 무결성 19개를 통과했다. 사건 키 참고 대조는 훈련 1 · 운영 0으로 불일치하며 숨기지 않는다. 백업 뒤 조치 2건 및 담당 지문 대상 1건은 복원본에 없고, 새 백업 한 벌로는 정기 백업 간격을 평가하지 못한다. [복원 결과와 한계](../2026-10-03-final-tls-restore/README.md).

19:05 최종 확인: A HTTPS health 200·실행 이미지 일치, B maint·VM 꺼짐, data01 자원 timer enabled/active와 적재·탐지 정상 종료, Mac 설치 감시 해시 일치·HTTPS 200·점검 창 없음. failover-probe 비활성·기존 세션 401·쿠키 제거, 격리 복원 DB/볼륨/폴더·SSH 터널·Mac 비밀 폴더 제거. 운영 알림 채널 설정과 기존 운영 판정은 보존했다(`final-runtime.json`, `probe-disabled.json`, `leave-production.log`, `restore-cleanup.log`).

Mac 감시의 UP 시작 시각은 이전 상태 파일의 연속 상태이며 이번 HTTPS 배포의 시작 시각이 아니다. 마지막 확인 시각과 주소로 새 판 점검을 확인한다. `SHA256SUMS`는 최종 증거 파일을 대상으로 계산한다. 개인키·실제 세션 쿠키·비밀번호·웹훅 주소는 포함하지 않는다.


`tools/`는 이 회차에서 실행한 도구의 보존 사본이다. 원래 실행 위치는 `output/final-development-20261003/deployment/`이며 일부 경로·백업명은 그 환경에 고정돼 있다. 증거 폴더에서 곧바로 다시 실행하는 범용 설치기로 제공하는 것이 아니다.
