# 관제 대상별 상태판 · 생존 신호 표 · 인시던트 CVE 배지 검증 (#52)

작업 브랜치: `feat/52-status-board-cve-badge` · 기준 커밋: `aab90aa`(디자인 정비, 같은 이슈의 별도 커밋).
대시보드 첫 화면에 관제 대상 카드 네 장을 두고, 사건 목록 · 대상 카드 · 사건 상세에 같은 값의 CVE 배지를 붙였다.
운영 반영은 아래 '운영 반영' 순서로 한다. 이 문서의 검증은 로컬 시험 DB와 로컬 앱 기준이다.

## 구현

| 항목 | 결과 |
|---|---|
| 관제 대상 카드 | AWS 센서(Cowrie · 웹 디코이 · AWS 관문) · web-01 · 관제 콘솔 · 데이터 노드. 구역은 수집 · 보안 · 최근 사건 · 시스템 · 대응 · 취약점 |
| 새 API | `GET /api/dashboard/targets`(app/targets.py). 반복 읽기 · 읽기 전용 트랜잭션 하나. 표 · 권한은 선검사로 갈라 '미확인' 으로 답한다 |
| 생존 신호 표 | `sensor_heartbeats`. 적재기(record_heartbeats.py, 적재 역할)가 업로더 신호를, 집행기가 관문 · 내부 방화벽 차단 보고 신호를 쓴다. 트리거가 역할별 행 종류 · 키 모양을 막는다 |
| DB 권한 | 콘솔 역할에 `sensor_heartbeats` · `node_metrics` 읽기(별도 블록, 20260924_db_roles.sql 은 그대로). 마이그레이션 `20260930_status_board.sql` 은 schema.sql 블록과 글자가 같다 |
| CVE 배지 | `GET /api/cti/badges?key=…`(1~100개). 상세 응답에 `badge` 추가. 목록 · 카드 · 상세가 같은 계산 함수를 쓴다 |

| 실시간 | 사건 · 판정 · 조치 통보와 재접속 때 카드도 다시 조회한다. 카드 조회 실패는 수치 · 대기열을 막지 않는다 |
| 설치 · 문서 | install-enforcer.sh 가 #47 → #51 → #52 순으로 적용. README 설치 명령 · 생존 신호 표 절 · 재적용 안내 갱신. 복원 훈련 기대값(표 26 · 트리거 7 · 함수 12) |

## 판정 규칙

| 구역 | 규칙 |
|---|---|
| 수집 | 정상 · 요청 없음 · 수신 없음 · 생존 상태 미확인 네 값, 늘 글자로 쓴다. 업로더 신호 끊김은 적재기가 확인한 시각 기준 15분(풀러 경고와 같은 기준), 적재기 멈춤은 지금 기준 30분 |
| 보안 | 최근 1시간 신규 · 높음 이상 · 전체 미판정. 사건 → 대상은 규칙 버전 정의의 발생원. 발생원이 섞인 규칙은 탐지와 같은 범위(고정 창 · 임계치 · 응답 코드 · 제외 경로)의 실제 이벤트로, 발생원 조건 없는 세션 규칙은 사건의 세션으로 고른다 |
| 대응 | 숫자 0 을 그리지 않는다. 적용 확인 n(초록) · 적용 실패 n(빨강) · 적용 여부 미확인 n(주의) · 정책상 차단 제외 n. 지점이 없으면 '차단 적용 여부 미확인'. 집행기 확인이 10분 넘게 멈추면 적용 확인을 미확인으로 합친다 |
| 취약점 | 자산 정보 없음 · 대조 전 · 48시간 넘음을 0 으로 꾸미지 않는다. CTI 표를 읽을 수 없으면 '취약점 정보 없음' 이고 다른 구역은 그대로다 |
| CVE 배지 | 'CVE n · KEV m · 해당 · 비해당 · 미확인'. 공개 정보가 48시간 넘게 오래되면 비해당을 미확인으로 읽는다 |

## 남은 것

- 사건 목록 · 대기열의 발생원 표기는 여전히 규칙 번호 기준이다. 그래서 R202(수집 경로 자기 감시)가 카드에서는 데이터 노드, 대기열에서는 '콘솔 · 감사' 로 보인다.
  표기와 판정 목표(R2xx 1시간)가 같은 규칙에 묶여 있어 따로 정한다.
- 탐지 근거에 발생원 목록이 없는 빈도 규칙(R101 w2 · R102)은 콘솔이 이벤트로 발생원을 다시 고른다. 근본 해법은 탐지가 근거에 발생원을 남기는 것(새 규칙 버전)이다.
- 콘솔 생존 표(console-b 꺼짐 표시) · 시간 동기화 · web-01 밖 자원 지표는 이슈 범위 밖이다.
