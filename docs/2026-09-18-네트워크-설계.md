# 네트워크 설계 — DMZ 와 내부망

작성일 2026-09-18 · WBS 2.5 · 초안 (값 확정 전)

관문 방화벽 뒤에 센서를 두고, 보호 대상을 내부망으로 내린다. 이 문서는 주소 · 경로 ·
방화벽 규칙을 확정하고, 각 규칙을 **어떻게 검증할 것인지**까지 함께 정의한다.
규칙표에 없는 통신은 전부 거부한다.

---

## 1. 전체 경로

```
인터넷
  │  22 · 23 · 8080 만 도달
  ▼
관문 방화벽 (공인 IP)                     [클라우드 · 상시 가동]
  ├─ 22 · 23 ──▶ 허니팟   10.0.21.10
  ├─ 8080  ───▶ 웹 디코이 10.0.21.20
  └─ 그 외 거부 · 기록
         │ 올리기만
         ▼
        S3 (게이트웨이 엔드포인트 경유)
         │ 가져오기 (내부에서 시작하는 연결)
         ▼
내부 방화벽                                [가상화 · 인터넷에서 도달 불가]
  ├─ 서비스망 192.168.50.0/24 — 콘솔 A · B · 보호 대상 web-01
  ├─ 데이터망 192.168.60.0/24 — 수집 · 탐지 · DB · 로그
  └─ 관리망   192.168.70.0/24 — 작업자 접근
```

---

## 2. 주소 설계

### 2.1 클라우드 (DMZ 구간)

| 구간 | 대역 | 배치 | 비고 |
|---|---|---|---|
| VPC | 10.0.0.0/16 | — | 기존 설계 승계 |
| 공개 서브넷 | 10.0.1.0/24 | 관문 방화벽 10.0.1.10 | 공인 IP 는 여기에만 붙는다 |
| DMZ 서브넷 | 10.0.21.0/24 | 허니팟 10.0.21.10 · 디코이 10.0.21.20 | 공인 IP 없음 |

- DMZ 서브넷의 기본 경로는 인터넷 게이트웨이가 아니라 **관문 방화벽의 네트워크 인터페이스**로 향한다.
- 방화벽 인스턴스는 출발지 · 목적지 확인을 해제해야 전달이 동작한다.
- S3 는 게이트웨이 엔드포인트로 접근하므로 DMZ 에 인터넷 경로가 없어도 로그를 올릴 수 있다.
- 보안그룹은 방화벽 규칙과 별개로 한 겹 더 둔다. 방화벽 규칙이 잘못되어도 보안그룹이 남는다.

### 2.2 가상화 (내부망)

| 세그먼트 | 대역 | 구성 | 메모리 |
|---|---|---|---|
| 서비스망 | 192.168.50.0/24 | 콘솔 A 192.168.50.11 · 콘솔 B 192.168.50.12 | 각 1GB |
| 서비스망 | 192.168.50.0/24 | 보호 대상 web-01 192.168.50.21 (sshd · nginx · Grafana Alloy) | 768MB |
| 데이터망 | 192.168.60.0/24 | 데이터 노드 192.168.60.11 (수집 관문 3101 · Loki(루프백) · 가져오기 · 탐지 · PostgreSQL) | 2GB |
| 관리망 | 192.168.70.0/24 | 작업자 단말(호스트) | — |
| 경계 | 각 망의 .1 | 내부 방화벽 겸 부하분산 (다중 인터페이스) | 1GB |

web-01 은 관제 대상 서버를 새로 붙이는 절차(화면 S-13)를 시연하기 위한 보호 대상이다.
인터넷에서 도달하지 않으며, 정상 사용 로그가 오탐률 측정의 기준이 된다.
메모리는 Mac 이 빠듯해 web-01 768MB · 데이터 노드 2GB 로 정했다(2026-09-21 실측: Alloy 실사용 41MB,
데이터 노드 PostgreSQL 80MB · Loki 33MB). 수집 구조는 `docs/2026-09-21-web01-수집-설계.md` 에 있다.

가상 스위치를 세그먼트 수만큼 만들고, 내부 방화벽 가상 머신만 모든 스위치에 연결한다.
세그먼트 간 통신이 방화벽을 지나가지 않을 수 없는 구조가 되어야 한다.

## 3. 방화벽 규칙

### 3.1 관문 방화벽 (클라우드)

| 방향 | 출발 | 목적 | 포트 | 처리 |
|---|---|---|---|---|
| 유입 | 인터넷 | 허니팟 | 22 · 23 | 전달 (허용) |
| 유입 | 인터넷 | 웹 디코이 | 8080 | 전달 (허용) |
| 유입 | 인터넷 | 그 외 전부 | — | **거부 · 기록** |
| 유출 | DMZ | S3 엔드포인트 | 443 | 허용 |
| 유출 | DMZ | 그 외 전부 | — | **거부 · 기록** |
| 내부 | 허니팟 ↔ 디코이 | — | — | **거부** |

- 거부 기록이 곧 탐지 자료다. 어떤 포트를 얼마나 두드렸는지가 방화벽 로그에 남는다.
- 유출을 막는 이유는 센서가 경유지로 악용되는 것을 방지하기 위해서다. 실제로 경유 시도 30건을 관측했다.
- 센서 간 통신을 막는 이유는 한쪽이 장악되었을 때 다른 쪽으로 번지지 않게 하기 위해서다.

### 3.2 내부 방화벽 (가상화)

| 방향 | 출발 | 목적 | 포트 | 처리 |
|---|---|---|---|---|
| 서비스 → 데이터 | 콘솔 A · B | 데이터 노드 | 5432 | 허용 |
| 서비스 → 데이터 | web-01 에이전트 | 데이터 노드 수집 관문 | 3101 | 허용 (등록 토큰 · 출발지 검사는 관문이 한다) |
| 데이터 → 인터넷 | 데이터 노드 | S3 | 443 | 허용 (로그 가져오기) |
| 서비스 → 인터넷 | 콘솔 A · B | 등록된 통보 채널 주소 | 443 | 허용 (채널 추가 시 허용 목록 반영) |
| 서비스 → 인터넷 | web-01 | 패키지 저장소 | 443 | 구성 창(provision 집합, 30분 자동 만료)에서만 허용 |
| 서비스망 안 | web-01 | 콘솔 A · B | 전부 | **거부** (같은 L2 라 방화벽을 지나지 않으므로 콘솔의 호스트 가드가 막는다) |
| 서비스 → 인터넷(그 외) | — | — | — | **거부** |
| 관리 → 전체 | 작업자 | 전 세그먼트 | 관리 포트 | 허용 |
| VPN → 방화벽 | 관리망 VPN(Tailscale) | 방화벽 HAProxy | 8443 · 22 | 허용 |
| VPN → 내부 노드 | 관리망 VPN | 서비스망 · 데이터망 | 22 | 허용 (DB · 앱 포트는 거부) |
| 데이터 · 서비스 → 관리 | — | 관리망 | — | **거부** |
| 인터넷 → 내부 | — | — | — | **전면 거부** |
| 데이터 → 인터넷(그 외) | — | — | — | **거부** |

콘솔은 인터넷에 열지 않는다. 밖에서는 관리망 VPN 으로만 들어온다. VPN 은 방화벽 VM 이 밖으로
연결을 열어 두는 방식(Tailscale 서브넷 라우터)이라 바깥에서 들어오는 포트를 열지 않는다 (2026-09-21 결정).

## 4. 규칙 검증 방법

설계는 규칙을 적는 것이 아니라 **적은 대로 동작함을 보이는 것**까지다. 각 항목을 아래 방법으로 확인하고 결과를 남긴다.

| 확인할 것 | 방법 | 기대 결과 |
|---|---|---|
| 허용 포트만 열려 있다 | 외부에서 포트 조사 | 22 · 23 · 8080 만 응답 |
| DMZ 가 내부로 갈 수 없다 | 허니팟에서 데이터 노드로 접속 시도 | 실패하고 방화벽에 거부 기록 |
| DMZ 가 인터넷으로 못 나간다 | 허니팟에서 외부 주소로 접속 시도 | 실패하고 거부 기록 |
| 센서끼리 통신하지 못한다 | 디코이에서 허니팟으로 접속 시도 | 실패 |
| 로그가 단방향으로만 흐른다 | 데이터 노드에서 가져오기 실행 | 성공. 반대 방향은 실패 |
| 거부 기록이 수집된다 | 방화벽 로그가 콘솔에서 조회됨 | 시각 · 출발지 · 포트가 남음 |
| 미등록 에이전트는 수집되지 않는다 | 토큰 없이 · 임의 키 · 다른 노드 키 · 폐기 키로 수집 관문(3101)에 전송 | 401 로 거부, 본문은 어디에도 저장되지 않고 R202 인시던트 생성 |
| 관제 대상은 수집 관문 외에 닿지 않는다 | web-01 에서 DB · Loki · 데이터 노드 22 · 콘솔 · 관리망 · 인터넷으로 접속 시도 (`scripts/verify.sh` 6장) | 모두 실패. 3101 만 통과 |
| 콘솔은 등록 채널로만 나간다 | 콘솔에서 임의 외부 주소로 접속 시도 | 실패. 채널 주소는 성공 |

이 표가 그대로 테스트 결과서(WBS 4.2)의 항목이 된다.

## 5. 아직 정하지 않은 것

| 항목 | 선택지 | 영향 |
|---|---|---|
| 상시 가동 서버 | 학교 자원 / 클라우드 DMZ | 있으면 클라우드를 걷어내고 관문 방화벽을 가상화 안으로 들인다. 내부 설계는 그대로다 |
| 사설 구간 관리 접근 | 세션 관리자 엔드포인트 / 방화벽 경유 | 엔드포인트는 월 약 28 USD. 크레딧이 들어오면 원안대로 "관리 포트 없음"을 유지할 수 있다 |
| 콘솔의 인터넷 노출 | 비노출 / 관문 8443 으로 노출 | 노출하면 콘솔에도 실제 공격이 유입되어 자동 차단의 대상이 생긴다. 대신 보호 대상이 하나 늘어난다 |
| 허니팟과 디코이의 분리 | 한 대 / 두 대 | 크레딧이 들어오면 분리한다. 세그먼트 설명과 격리가 명확해진다 |
| 가상화 네트워크 모드 | 사용자 정의 스위치 구성 | 호스트 공유 방식과 격리 방식의 조합을 구축 시 확정한다 |
