# 탐지 규칙 추가 결과 (WBS 3.5.1 · 3.5.4 · 이슈 #14)

작성일 2026-09-22 · 선행 문서 `docs/2026-09-21-web01-수집-결과.md`, `docs/2026-09-08-판정-기준.md`

지금까지 규칙은 허니팟(R001 ~ R005)과 미등록 에이전트(R202)뿐이었다. 디코이 · 콘솔 · web-01 로그를 모으지만 보는 규칙이 없었다.
이 작업은 웹 인증 규칙군(w1), 차단 목록 감사 규칙(a1), 노드 수신 끊김 규칙(i1)을 더한다. 셋 다 1분 다리에서 돈다.
허니팟 규칙(v1 · v2)과 5분 적재기는 바꾸지 않는다.

**운영 배포 전이다.** 탐지기(detect.py)를 허니팟 5분 경로와 같이 쓰므로 허니팟 48시간 병행 대조(9/23 21:40 KST)가 끝난 뒤에 배포한다 (6장).

임계치 근거는 규칙 파일의 rationale 에 있다. 요약하면:

- R101 은 관측 근거가 없다(디코이 실패 0 · web-01 실패 0 · 콘솔 4건). fail2ban 기본값(10분 5회)과 허니팟 R001(15분 5회)을 이었다.
- R102 는 디코이 4일 관측(출발지별 10분 창 최대 4)에서 관측 최대를 넘는 최소 정수 5 다. web-01 · 콘솔은 이 값을 빌린다.
- R103 · R104 · R201 은 양성 표본이 0건이다. 합성과 사전 정의로만 말한다. 판정 지표를 수치로 주장하지 않는다.
- R201 의 사전 정의: 판정 뒤 건별로 풀고, 한 판정에 최대 2건 · 10분.
- R301 은 화면 설계 S-08 의 정의(10분 안에 받으면 정상)를 따른다. 정상 수신 간격 상한은 약 2분이다.
- 모두 폐루프 2회차(3.8.2)에서 다시 정한다.

R101 · R102 는 기존 actor_rate(고정창)를 쓴다. 창 경계에 걸친 연속 실패(4+4)는 잡지 않는다. 허니팟 R001 과 같은 성질이다.

## 2. 바꾼 것

| 위치 | 내용 |
|---|---|
| detector/detect.py | actor_rate 에 선택 조건 http_status. 새 유형 operator_rate(사람 단위 미끄럼 창) · node_silence(적재 공백). 신호를 (출발지, 대상)으로 묶고, IP 가 아닌 대상(`user:` · `node:`)은 incidents.target 에 넣는다. 기존 문장 · 적재 문장(INSERT_BASE)은 글자 그대로다 |
| detector/rules_w1.json · rules_audit.json · rules_infra.json | 새 규칙 파일 세 개. rules_node.json(n1)은 그대로 두고 실행만 뺀다 (w1 R101 이 흡수) |
| infra/schema.sql 끝 멱등 블록 | incidents.target · node_metrics.loaded_at · blocklist.released_by · 차단 목록 감사 트리거 · audit_log 뷰 · 감사 행 추가 전용 보호 |
| infra/notify.sql | 알림 페이로드에 target. target 열이 없는 DB 에서도 실패하지 않게 `to_jsonb(NEW) ->> 'target'` 으로 읽는다 |
| app/main.py | 조치 트랜잭션 첫 문장에서 행위자를 넘긴다(set_config). 해제는 살아 있는 차단만, 해제자를 남긴다. 재차단은 살아 있는 차단의 만료를 줄이지 않는다. 인시던트 조회에 target 과 target 필터 |
| detector/triage.py | 대상 표시. 판정자를 감사 트리거에 넘긴다. 되살린 차단은 만료를 비운다(triage 차단은 영구) |
| collector/pull_loki.py · install-collector.sh | 1분 다리가 s1 · w1 · a1 · i1 을 따로 돈다. 하나가 실패해도 나머지는 돈다 |

**차단 목록 감사** (R201 의 입력)

- 트리거가 차단의 해제 · 만료 변경을 events(sensor='audit')에 남긴다. 콘솔을 거치지 않은 psql 직접 변경도 남는다.
- 행위자는 앱이 넘긴 사용자, 없으면 `db:<DB 역할>` 이다.
- 살아 있는 차단을 풀면(UPDATE · DELETE · 주소 변경) 모두 `console.block.released` 다. 만료를 앞당기면 `shortened`, 늦추면 `extended` 다.
- 만료는 어디서도 집행하지 않고 활성은 `released_at IS NULL` 로만 정한다. 그래서 만료가 지난 차단을 푸는 것도 해제다. 만료가 지났는지는 input 의 `past_expiry` 로만 남긴다.
- sensor 를 console 로 두지 않는다. 허니팟 R005(기준선)가 console 을 세므로 입력이 바뀐다.
- 잔여 위험: DB 역할 opsloop 가 슈퍼유저라 트리거를 끄거나 TRUNCATE 로 감사를 피할 수 있다. 앱 경로와 실수는 남기지만 의도적인 우회는 막지 못한다.

### 합성 시나리오 (DB 사본)

- R101 · R102: 발생원별 6회는 뜨고 4회는 뜨지 않는다. 200 응답 · 목록 밖 eventid 는 세지 않는다.

- R201
  - 10분에 2건은 0, 1분에 3건은 1.
  - 600초 안에 꼭 들어가면 1, 1µs 넘으면 0.
  - 고정창이면 2+2 로 갈릴 4건도 미끄럼 창이라 1.
  - 콘솔 A · B 출발지 교대와 psql 직접 변경(`user:db:opsloop`)도 잡는다.
  - 이미 풀린 차단을 다시 풀면 감사 행이 없다.
  - 만료가 지난 차단 · 미래 시각으로 푼 차단도 해제로 센다.
- R301
  - 관제가 매분 돈 20분 공백은 1, 관제 기록이 없는 30분 공백은 0.

### 콘솔 문장

main.py 의 새 문장을 글자 그대로 꺼내 사본에서 실행했다.

- 해제: 살아 있는 차단만 풀고 해제자를 남긴다. 이미 풀린 차단은 바꾸지 않는다(전에는 해제 시각을 덮어썼다).

- 감사 행을 고치거나 지우면 오류로 거부된다.

## 4. 알려진 한계

1. **콘솔 출발지가 인프라 주소로 묶인다.**
   - 콘솔이 실제 클라이언트 주소를 받기 전에는 console.login.failed 의 출발지가 인프라 주소다. 9/22 덤프는 도커 브리지 172.18.0.1 이고, 내부망에서는 HAProxy 192.168.50.1 일 수 있다.
   - 그래서 R101 이 콘솔 사용자 전원을 한 행위자로 묶는다. 그 인시던트의 차단은 인프라 주소를 막는다.
   - 출발지를 확인한 뒤 판정하고, 차단 금지 목록은 3.9 에서 둔다.
2. **R103 은 사실상 '디코이 로그인 성공'이다.** 디코이는 로그인 성공 뒤 리디렉트된 대시보드에서 행위 1건을 남긴다. 양성 표본 없이 조건을 고치면 추측이므로 w2 후보로 둔다.
3. **인시던트는 처음 모습으로 굳는다.** 기존 적재 방식(ON CONFLICT DO NOTHING) 그대로다. 진행 중에 뜬 R301 의 복구 시각은 증거에 반영되지 않는다.
4. **R301 은 관제가 산 분이 8 이상일 때만 뜬다.** 다리 회차가 느려지면 그만큼 늦게 뜬다.
5. **같은 시각 행이 여럿이면 R201 증거의 순서가 정해지지 않는다.** 키 · 건수에는 영향이 없다.

## 6. 배포 순서

1. 허니팟 48시간 병행 대조가 끝나기를 기다린다 (9/23 21:40 KST 이후).
2. 9/8 차단 13건의 만료를 채울 일이 있으면 **트리거를 설치하기 전에** 한다. 13건 모두 만료가 NULL 이라, 트리거 뒤에 채우면 shortened 13건이 생겨 R201 이 뜬다.
3. data-01 에 `infra/schema.sql` 을 적용하고, `infra/notify.sql` 도 손으로 적용한다(설치 스크립트가 적용하지 않는다).
4. **곧바로 콘솔 A · B 를 재빌드한다.** 트리거가 있는 상태에서 옛 콘솔로 차단 · 해제를 하면 행위자가 db:opsloop 로 남는다. 옛 콘솔은 만료 없는 차단에 24시간을 덮어 shortened 를 남기므로, 10분에 3건이면 R201 오탐이 난다.
5. 코드를 배포한다 (`install-ingest.sh <커밋>` → `install-collector.sh <커밋>`). detect.py 와 규칙 파일은 한 커밋이다.
6. 첫 회차에 R301 과거 인시던트 1건(9/21 13:26 web-01)과 알림 1건이 나온다. 기존 지표의 적재 시각을 ts 로 채웠기 때문이고, 실제 수집 중단이라 정탐이다.
7. R301 리허설을 한다.
