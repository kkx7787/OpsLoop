# 수집 파이프라인 이전 결과 (WBS 3.4 · 이슈 #10)

작성일 2026-09-21 · 선행 문서 `docs/2026-09-21-내부망-구축-결과.md`, `docs/2026-09-18-네트워크-설계.md`

센서(허니팟)가 DB 비밀번호를 들고 AWS DB 에 직접 넣던 경로를 끊는 작업이다.
센서는 원문 로그를 S3 원장에 **올리기만** 하고, 파싱 · 탐지는 내부망 데이터 노드가 **가져가서** 한다.

---

## 1. 바꾼 것

```
[전]  허니팟 ──(DB 비밀번호로 직접 접속, 5432)──▶ AWS 앱 노드 DB
[후]  허니팟 ──(올리기만, 443)──▶ S3 원장 ◀──(가져가기만, 443)── 내부망 데이터 노드 ──▶ 내부 DB
```

- 센서가 장악돼도 공격자가 얻는 것은 "원장에 새 조각을 올릴 권한"뿐이다. DB 주소도 비밀번호도 없다.
- 연결은 항상 안에서 밖으로 시작한다. 밖에서 내부망으로 들어오는 연결은 여전히 없다.
- 원문 로그가 원장이고 DB 는 파생물이라는 원칙을 그대로 유지한다. 원장만 있으면 DB 를 다시 만들 수 있다.

## 2. 구성

| 위치 | 구성요소 | 내용 |
|---|---|---|
| 허니팟 | `sensor/upload.py` · `opsloop-upload.timer` (5분) | 새로 쌓인 줄만 올린다. inode 로 위치를 기억해 자정 회전 뒤에도 이어 올린다. 반쪽 줄은 다음 회차로 미룬다. 줄 내용은 바꾸지 않는다 |
| 허니팟 | 역할 `opsloop-sensor-role` | `raw/*` · `hb/*` 에 `PutObject` 만. 읽기 · 목록 · 삭제 없음. IMDS hop limit 1 (컨테이너가 역할 자격증명을 못 가져간다) |
| S3 | `opsloop-archive-739272173045` | 버저닝 켬. 버킷 정책 4개: 비TLS 거부 · 원장 쓰기는 센서 역할만 · 원장은 한 번만 쓰기(`If-None-Match` 없는 쓰기 거부) · 원장 삭제 거부 |
| 데이터 노드 | 사용자 `opsloop-archive-reader` | `raw/*` · `hb/*` 목록과 읽기만. 키는 Terraform 이 아니라 CLI 로 발급해 파이프로 바로 넣었다 (tfstate · Mac 디스크 · 대화에 남지 않음) |
| 데이터 노드 | `puller/pull.py` · `opsloop-ingest.timer` (5분) | 생존 신호를 먼저 읽고 그 전에 올라온 조각만 받는다. SHA256 대조 · 줄바꿈 확인 뒤 미러에 두고, 받은 편지함의 새 조각만 파서에 넘긴다. 구멍이 있으면 탐지를 보류한다 |
| Mac | `infra/vmware/scripts/backup-db.sh` | 관리망 ssh 로 내부 DB 덤프를 Mac 에 받는다. 14개 보관. `VERIFY=restore` 로 임시 DB 복원 시험 |

키 구조

```
raw/v1/sensor=<cowrie|decoy>/host=<인스턴스 ID>/ino=<inode>.g<세대>/<시작 12자리>-<끝 12자리>.jsonl
hb/v1/host=<인스턴스 ID>/latest.json      업로더 생존 신호. 파일별 올린 위치가 적혀 있다
```

## 4. 병행 대조

AWS 경로(허니팟 → AWS DB)는 지우지 않고 같이 돌린다. 두 경로가 같은 원문을 읽으므로 결과가 같아야 한다.

## 5. 설계에서 바꾼 점

- **받은 편지함 방식.** 계획은 매 회차 미러 전체를 다시 파싱하는 것이었다. 파서가 줄 단위로 처리하고 세션은
  DB 에서 다시 집계하므로 새 조각만 넘겨도 결과가 같다. 그래서 새 조각만 편지함에 걸고, 적재가 끝나면 편지함에서만 뺀다.
  적재가 실패하면 편지함에 남아 다음 회차에 다시 들어간다. 조각이 쌓여도 회차 시간이 늘지 않는다.
- **생존 신호 기준 절단.** 목록을 먼저 보고 생존 신호를 나중에 읽으면, 업로더 회차 도중에 회전 직전 파일의 꼬리는 없고
  새 파일만 있는 순간을 잡을 수 있다. 그 상태로 탐지하면 쪼개진 인시던트가 영구히 남는다.
  생존 신호를 먼저 읽고, 그보다 늦게 만들어진 조각은 다음 회차로 미룬다. 시각은 S3 가 찍은 값만 쓴다.
- **원장 덮어쓰기 자체를 막았다.** 계획은 덮어쓰기를 감지해 경보하는 것이었다. 버킷 정책으로 `If-None-Match` 없는 쓰기를
  거부하므로 센서 역할도 이미 있는 조각을 덮어쓸 수 없다. 풀러의 변조 경보는 정책이 풀렸을 때를 위한 두 번째 방어선으로 남긴다.
- **허용 목록.** 목록 밖 호스트 · 규칙에 맞지 않는 키는 받지 않고 한 번만 알린다.

## 6. 코드 검토와 수정

배포 뒤 검토자 4명(원장 · 보안 · 운영 · 연동 관점)이 코드를 읽고, 관점마다 반박 담당이 지적을 직접 재현해
확정했다. 확정 24건(관점 간 중복을 합치면 약 15건)과 누락 점검 1건을 모두 고쳤다.

| 구분 | 결함 | 수정 |
|---|---|---|
| 인터넷에서 요청 한 번 | NUL 문자 · 긴 쿠키가 든 로그 한 줄이 DB 적재를 실패시키고, 같은 파일이 매 회차 다시 실패해 적재와 탐지가 영구히 멈춤 (AWS 옛 경로도 같은 파서) | 파서가 NUL 을 지우고 색인 열(세션 · 이벤트 ID)을 자르며, 객체가 아닌 JSON · 범위 밖 정수 · 주소가 아닌 src_ip 를 걸러 낸다. 적재기는 파일 단위로 격리한다 |
| 센서 장악 | GLACIER · 외부 KMS 로 올린 조각 하나로 풀러가 매 회차 죽음 | 버킷 정책이 기본 저장 등급 · 기본 암호화 외 업로드를 거부(센서 역할로 확인). 풀러도 조각별 오류를 격리 |
| 센서 장악 | 키 끝 줄바꿈으로 받기 전 조각을 조작본으로 바꿔치기 | 키 전체 일치 검사, 편지함 이름 충돌 시 덮어쓰지 않음 |
| 센서 장악 | 큰 조각 · 대량의 잘못된 키로 메모리 · 디스크 고갈 | 조각 64MiB 상한, 회차당 512MiB, 디스크 여유 2GiB · 10% 하한(미달 시 13), 상태 목록 상한, 허용 호스트 접두사만 조회, 파서는 5천 줄씩 흘려 넣음 |
| 센서 장악 | 가짜 조각 · 가짜 생존 신호로 탐지가 영구 보류되거나 풀러가 죽음 | 생존 신호 형식 검증(틀리면 11), 운영자 구멍 인정 목록 |
| 센서 장악 | 줄바꿈이 든 키로 가짜 로그 줄 · 등급 생성 | 로그에 쓰는 외부 값의 제어 문자를 이스케이프 |
| 센서 장악 | 디코이 줄의 sensor 값을 믿어 콘솔 인증 기록 위조 | 디코이 파서는 sensor 를 항상 decoy 로, 이벤트 ID 는 decoy. 접두사만 받는다 |
| 운영 | 업로더가 멈춰도 서비스는 성공(0) | 생존 신호가 없거나 15분 넘게 멈추면 11 로 실패 표시 |
| 운영 | 업로드에 실패한 파일 · 회전 경합이 구멍 검사를 피함 | 끝나지 않은 회차에는 업로더가 생존 신호를 쓰지 않는다 |
| 운영 | 거부한 조각을 매 회차 다시 받음, 상태 파일을 조각마다 다시 씀, 편지함 수만 개면 삭제 명령 인자 초과 | 거부 기록(ETag 기준), 200개 · 30초마다 저장, 적재기를 Python 으로 옮겨 200개 · 32MiB 묶음 처리 |
| 운영 | DB 를 백업에서 복원하면 원장에서 다시 채울 수단이 없음 | `opsloop-ingest --full` (아래 절차) |
| 운영 | 백업 복원 시험이 실패하면 사본 DB 가 운영 컨테이너에 남음 | 정리 trap, 운영 DB 와 건수 대조, 실패 시 `.unverified` 로 보존 |
| 운영 | 재설치 때 설정 파일을 덮어써 추가한 센서 호스트가 빠짐 | 이미 있으면 덮어쓰지 않음 |
| 누락 점검 | v2 규칙의 억제가 판정 전 조치(확인 · 차단) 기록을 CASCADE 로 지움 | 조치가 붙은 인시던트도 억제 삭제에서 제외 |

수정 뒤 같은 방식으로 다시 공격해 검증했다(검증자 4명 · 회귀 탐색 2명 · 누락 점검 1명). 25건 중 15건은 막혔고,
10건은 일부만 막혔으며, 수정이 만든 회귀 1건(high)이 나왔다. 2차 수정으로 모두 고쳤다.

| 2차 수정 | 내용 |
|---|---|
| 회귀 | S3 에서 받는 도중 연결이 한 번 끊겨도 그 조각을 "영구 거부"로 기록해 영구 구멍 · 전역 탐지 정지가 되던 것. 내용 검증 실패와 보관 등급 오류만 거부로 기록하고, 연결 · 시간 초과 · 5xx 는 다음 회차에 다시 받는다 (그 회차는 1 로 실패 표시, 탐지 보류) |
| 풀러 | 생존 신호의 무한대 · 실수 값으로 풀러가 죽던 것(정수만 받고 호스트별로 격리), 유니코드 숫자 키로 편지함 이름을 겹쳐 바꿔치기하던 것(ASCII 숫자만 · 키 원문으로 이름 · 충돌 시 거부), 거부 목록이 차면 같은 조각을 매 회차 다시 받던 것(세대 단위로 멈춤), 실패한 받기가 회차 한도에 안 들던 것(바이트 · 요청 수 · 600초), 디스크 부족 · 한도로 미룬 조각을 "인정하라"고 안내하던 것(일시 구멍으로 따로 표시) |
| 적재기 | 격리 파일이 많으면 매 회차 시간 초과로 탐지까지 멈추던 것. 적재 · 탐지를 먼저 하고 격리 재시도는 회차당 20개, 5분 → 1시간 간격. 파서에 메모리 상한 384MB, 서비스 `OOMPolicy=continue` |
| 파서 | IPv6 영역 ID · 4300자리 넘는 정수 · 짝 없는 서로게이트 · 4MiB 넘는 줄 |
| 업로더 | 회차 상한에 걸려 덜 올린 파일이 있으면 생존 신호를 쓰지 않는다 |
| 백업 | 지난 실행이 남긴 시험 DB 를 시작할 때 치우고, 정리에 실패하면 경고 |

실제 원장 전체(cowrie 10,900행 · decoy 337행)를 옛 파서와 새 파서로 읽어 만든 행이 **완전히 같다**.
방어 코드는 비정상 줄에만 작동한다. 시험은 72개(풀러 33 · 적재기 11 · 업로더 16 · 파서 12)다.

### 원장 구멍을 확인한 뒤 풀기

구멍 로그의 세대 이름(예: `cowrie/i-058726c1a0671fe1d/ino=123.g0`)을 확인하고, 원인이 센서 이상이나 조작이라고
판단되면 인정 목록에 넣는다. root 만 고칠 수 있다.

```
sudo python3 -c 'import json,sys; p="/etc/opsloop/gap-ack.json"; a=json.load(open(p)); a.append(sys.argv[1]); json.dump(a,open(p,"w"))' 'cowrie/i-058726c1a0671fe1d/ino=123.g0'
```
