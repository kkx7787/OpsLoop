# 폐루프 3회차 — 정상 트래픽 리플레이 (이슈 #49 · WBS 3.7 · 3.8.2)

기록일 2026-09-28 · 규칙 w2(현행)와 임계치 후보 w2-c3 · w2-c8 · 정상 시나리오 16개(66행) · 판정 10건(실험 DB · 정상 구간 9 + 9/18 콘솔 자체 시험 1) · 승격 없음 · 기준 `docs/2026-09-08-판정-기준.md` · 정의서 `docs/2026-09-28-정상-트래픽-정의.md`

1 · 2회차는 허니팟 규칙을 판정으로 고쳤다. 허니팟에는 정상이 없어 거기서는 재현율만 잴 수 있다.
3회차는 반대쪽이다. 디코이에서 뽑은 R101(인증 반복 실패) · R102(404 반복)를 **정상이 있는 구간**에 다시 돌려
정상 사용이 걸리는지 세고, 같은 후보를 디코이 구간에 다시 돌려 알려진 양성이 남는지 본다(웹 디코이 설계 §6 의 2 ~ 4번).
콘솔 · web-01 에는 실사용이 거의 없어 정상 구간이 없었다. 그래서 정상 사용을 미리 정의해(정의서) 실험 DB 사본에만 넣었다.
운영 콘솔 · web-01 · 허니팟 · 디코이에는 아무것도 보내지 않았고 운영 DB 는 읽기만 했다.

이 회차는 규칙을 바꾸지 않는다. 결과표까지다. 시각은 모두 UTC 다.

  R105 는 경로 서명을, R102 는 404 수를 보므로 판정 기준 §6 의 순환이 아니다). 172.237.27.147 은 판정(무시 가능 = 규칙은 맞았다)이 있다.

  구간 실행에 함께 잡혔다. 정상 시나리오 C03(오타 4회)과 같은 모양의 실제 사례다. 우리 운영 행위(콘솔 자체 로그인 시험)이지

## 4. 나란히 — 후보 | 콘솔 · web-01 오탐 | 디코이 재현율

```
후보     임계치   정상 시나리오 걸림 (16개 중)   R101   R102   디코이 R102 재현율 (양성 2)   양성 2 밖 추가 사건
w2         5           3                       2      1          2/2                          0
w2-c3      3           6                       3      3          2/2                          1  (R101 · 콘솔 자체 시험 9/18)
w2-c8      8           0                       0      0          2/2                          0
```

- 왼쪽은 설계값이다. 정상 시나리오의 최대가 5회이고 경계 3 · 4 · 5회를 넣었으므로 w2 3 · c3 6 · c8 0 은 표를 만들 때 정해졌다.
  오른쪽은 관측이지만 분포가 양극이라 후보를 가르지 못한다(c3 의 2/2 는 구성상 보장 · 3절).
- 그러므로 이 표는 '어느 임계치가 낫다' 를 말하지 않는다. 말하는 것은 셋이다. ① 현행 w2 에서 걸리는 정상은 정확히 '10분 안 5회'
  경계의 두 시나리오(콘솔 · SSH)와 404 5회 하나다. ② 임계치를 3 으로 내리면 오타 4회 · 404 3 ~ 4회가 추가로 걸리고 얻는
  재현율은 없다. ③ 8 로 올리면 정상 오탐은 0 이 되지만 잃는 재현율도 0 이라, 8 이 옳다는 근거도 아니다(디코이 양성이 224 · 256
  뿐이라 5 ~ 8 사이를 갈라 줄 관측이 없다).
- **규칙 버전은 올리지 않는다.** w3 로 바꾸면 웹 사건 키가 전부 바뀌어 기존 사건이 새 키로 다시 뜨고 콘솔 통보가 다시 나간다
  (rules_w1.json note). 임계치를 옮길 관측 근거가 이 표에는 없다. 승격은 별도 결정이다(7절).

## 6. 이 회차에서 확인된 것 · 한계

확인된 것

- 정상 사용을 사전에 정의해 실험 DB 사본에 넣고, 같은 구간에 후보 셋을 돌려 걸린 정상을 오탐으로 판정하는 절차가 끝까지 돈다.
  넣기 전후 기존 사건 키 1,027개의 md5 가 같고, 실험 DB 밖으로는 아무것도 나가지 않았다.
- 현행 w2 에서 걸리는 정상은 10분 5회 경계의 세 시나리오(C04 · S03 · W04)다. 오타 2회 · 4회, 404 2회 · 4회, 메타데이터 404,
  헬스체크, 성공만 있는 접속은 걸리지 않는다.
- w2 의 메타데이터 제외는 W05 6건 · W07 3건 · 운영 128.1.47.89 3건을 뺐다. 2회차의 처방(조건 변경 · 임계치 유지)이 정상 쪽에서도 뜻대로 동작한다.
- 디코이 알려진 양성 2건은 세 후보 모두 유지한다(2/2). 다만 분포가 양극이라 이 값은 후보를 가르지 못한다.

한계

- **설계값.** 작업자 1명 · 출발지 2개 · 시나리오 16개다. 걸린 건수는 정의서가 정했다. '오탐률 x%' 로 읽지 않는다.
  분모 · 구간 · 규칙 버전 · 출처를 뗀 비율을 이 문서 밖으로 가져가지 않는다.
- **출발지 뭉침.** web-01 SSH 는 fw ProxyJump 로 192.168.50.1 하나다(운영 9/27 17건 전부). S03 의 사건은 한 사람의 오타 5회와
  다섯 사람의 오타 1회씩을 가르지 못한다. 콘솔은 #43 뒤 갈리지만 확인은 운영 1건이다.
- **분모가 작다.** 정상 16 · 디코이 양성 2 · 실제 정상 사용 1. 통계가 아니다.
- **순환.** 시나리오 표가 임계치 5 를 알고 경계에 맞춰 만들어졌다. 16/16 일치는 구성상 보장된다(2회차 §5 대조군과 같은 성질).
  재현율 쪽도 라벨 집합이 w2 가 띄운 사건이라 규칙 밖 근거(경로 다양성 · 판정 1건)를 3절에 따로 적었고, 임계치 아래 창에는 라벨이
  없어 FN 은 집합 안에서만 0 이다. c3 의 2/2 는 구성상 값이다.
- **판정이 기준 적용이다.** 10건(정상 구간 9 · 9/18 콘솔 자체 시험 1)은 정의서 5절을 SQL 로 적용한 것이라 판정 소요 시간이 없다. 판정 비용은 이번에도 재지 않았다.
- **10분 고정창.** 창 경계에 걸친 4 + 4 는 어느 후보도 잡지 않는다. 시나리오는 창 안에 넣었다.
- **R101 은 디코이 라벨이 없다.** 로그인 시도 이벤트가 전 기간 0건이라 재현율 쪽이 비어 있다. 관측 부재인지 기록 누락인지
  아직 가릴 수 없다(9/22 문서 77행 정정).
