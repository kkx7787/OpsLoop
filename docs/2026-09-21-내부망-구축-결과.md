# 내부망 구축 결과 (WBS 3.3 · 이슈 #8)

작성일 2026-09-21 · 대상 VMware Fusion (MacBook Air M2 16GB) · 선행 문서 `docs/2026-09-18-네트워크-설계.md`

보호 자산을 인터넷에서 닿지 않는 내부망으로 내렸다. 관제 대상 서버 web-01 은 여기가 아니라
학교 AWS 계정에 두기로 했으므로(2026-09-21 결정) VM 은 4대다.

---

## 1. 구성

| VM | 메모리 · CPU | 주소 | 역할 |
|---|---|---|---|
| opsloop-fw | 1GB · 2 | uplink(NAT) 192.168.181.133 · 서비스망 192.168.50.1 · 데이터망 192.168.60.1 · 관리망 192.168.70.254 | 내부 방화벽(nftables) 겸 부하분산(HAProxy) |
| opsloop-console-a | 1GB · 1 | 192.168.50.11 | 관제 콘솔 |
| opsloop-console-b | 1GB · 1 | 192.168.50.12 | 관제 콘솔 예비 |
| opsloop-data-01 | 3GB · 2 | 192.168.60.11 | PostgreSQL |

- 가상 네트워크 3개를 만들고 DHCP 를 껐다. 주소는 노드마다 고정이다.
- 서비스망 · 데이터망은 Mac 에 연결하지 않았다. Mac(192.168.70.1)은 관리망으로만 들어간다.
- 기본 VM 한 대를 설치하고 **연결 복제**로 4대를 만들었다. 디스크는 바뀐 부분만 차지한다.
- 접근 경로: `ssh ops@192.168.70.254` → 거기서 `-J` 로 내부 노드.

## 2. 검증 (설계 4장의 표)

| 확인할 것 | 결과 |
|---|---|
| 콘솔 → 데이터 노드 5432 (허용) | 통과 |
| 콘솔 → 데이터 노드 22 · 9999 (규칙 없음) | 차단 |
| 데이터 노드 → 관리망 | 차단 |
| 데이터 노드 → S3 443 | 통과 |
| 콘솔 → 임의 주소 80 (규칙 없음) | 차단 |
| 콘솔 → 통보 채널 443 | 통과 |
| 거부 기록 | 방화벽 로그에 279건 |

규칙표에 적은 대로 동작했다. 패키지 저장소는 HTTP 대신 HTTPS 로 바꿔 80 포트를 열지 않았다.

## 3. 데이터 이전

AWS 앱 노드(i-0030bed49b6ef0356)의 데이터베이스를 내부망으로 옮겼다.

- 경로: 앱 노드에서 `pg_dump -Fc` → S3(`opsloop-archive-739272173045/migration/`) → **데이터 노드가 서명된 임시 URL로 가져감**
- 데이터 노드에는 AWS 자격 증명을 두지 않았다. "센서는 올리기만, 안쪽이 가져간다"는 원칙을 그대로 지켰다.
- 앱 노드 역할에는 해당 버킷 **올리기 전용** 권한만 부여했다.
- 무결성: 업로드 전후 SHA256 일치 (`0a63c602…36c7c`)

| 테이블 | AWS | 내부망 |
|---|---|---|

| sessions | 2,580 | 2,580 |
| incidents | 275 | 275 |
| verdicts · actions | 32 · 32 | 32 · 32 |

재생성이 불가능한 판정 · 조치 기록이 그대로 넘어왔다.

## 4. 이중화 실측 (WBS 4.4 선행)

HAProxy 설정은 검사 2초 · 연속 실패 3회 · 복귀 연속 정상 3회 · 가중치 상향 30초다.

| 시험 | 설계 상한 | 실측 |
|---|---|---|
| 콘솔 A 강제 종료 → 전환 | 최대 6초 | 요청 60건 중 2건 실패 (약 2초) |
| 콘솔 A 재기동 → 복귀 | 연속 정상 3회 | 약 8초 뒤 UP (`DOWN 2/3` 단계 관측) |

0.5초 간격으로 요청을 보내며 측정했다. 실패 구간이 짧은 이유는 컨테이너를 멈추는 순간
연결이 거부되어 헬스체크가 즉시 실패로 잡혔기 때문이다.

## 5. 막혔던 곳과 해결

| 문제 | 원인 | 해결 |
|---|---|---|
| 무인 설치(autoinstall)가 동작하지 않음 | macOS `hdiutil` 이 만든 ISO 에서 파일 이름이 `USER-DATA` 로 대문자 변환됨. 클라우드 설정은 소문자만 인식 | 수동 설치로 전환. 기본 VM 한 대만 만들면 되므로 영향이 작다 |
| 가상 네트워크가 생기지 않음 | Fusion 서비스가 앱 실행 시에만 올라옴 | 앱 실행 후 `vmnet-cli --configure/--stop/--start` |
| AWS 앱 서버 SSH 호스트 키가 바뀜 | 접속 주소가 앱 서버가 아니라 **허니팟(43.201.71.8)** 이었음. Cowrie 가 자기 키를 내민 것 | 앱 서버는 54.180.150.40. 관리 접근은 SSH 가 아니라 SSM 으로 한다(ADR-12) |
