# 관제 조치 의미와 브랜딩 보완 (#107)

## 규칙 억제라고 표시하던 조치

기존 `suppress_rule` API는 `incidents.status`를 `suppressed`로 바꾸고 조치 이력을 남길 뿐, 탐지 규칙을 중단하지 않았다. 대시보드·목록 API의 미판정 집계도 판정 기록 유무를 사용하므로 대기에서 빠지지 않았다. 반면 목록의 경과 강조는 suppressed를 제외해 같은 사건을 다르게 보였다.

새 화면에서는 이 조치 버튼과 규칙을 끈다는 확인 문구를 제거한다. 사건을 처리할 때는 기존 판정 흐름을 사용한다. 옛 API 값과 저장된 이력은 호환을 위해 남기되 화면의 이력 이름을 `사건 상태 억제`로 바꾼다. 미판정 경과는 상태와 무관하게 판정 기록이 없으면 표시한다. 탐지 단계의 규칙 간 흡수·억제, 규칙 배포·승인은 이 변경과 관계없다.

## 담당 동선과 알림 실패 안내

대시보드 제목 옆 `내 담당 미판정` 링크는 `/incidents?assignment=mine&judged=false`로 이동한다. 관제사·관리자에게만 보이며 집계하지 않은 개인별 숫자를 붙이지 않는다. 사건 목록의 담당 조건·기존 장비 조건·정렬은 함께 사용할 수 있다.

#103의 웹훅 전송에서 목적지 검증 실패와 발송 작업자 부족을 원인·다음 조치로 설명한다. 채널 주소나 응답 본문을 공개하지 않는다. DNS 실패·TLS 오류·HTTP 실패의 기존 설명은 유지한다.

## 로고

사용자가 고른 가운데 안을 바탕으로 로그인 워드마크, 사이드바 화살표, favicon을 맞춘다. 작은 크기에는 글자를 넣지 않고 남색·파란색 두 화살표를 쓴다. 본문 글꼴·로그 표·상태색은 유지한다. 생성 프롬프트와 자산 설명은 `app/branding/README.md`에 있다.

로그인 전에는 버전이 붙은 로고 두 경로만 공개한다. `/brand` 전체나 일반 `/assets`를 공개하지 않는다. CSP의 외부 이미지·인라인 스크립트 차단도 유지한다.

## 확인

2026-10-03 로컬 표본 미리보기에서 로그인, 밝고 어두운 바탕의 16~64px 아이콘, 1440·1024·390px 대시보드를 확인했다. 1024·390px에서 문서 가로 넘침은 없고 1024px 로그의 요청 경로도 표시된다. 표본 데이터와 읽기 전용 응답을 사용했으며 실제 운영 API나 배포 결과가 아니다.

화면 시험 70개 파일 1,104개, TypeScript·Vite 빌드, 린트 통과. 웹 계층 시험 86개 중 85개 통과·로컬에 asyncpg가 없어 실제 드라이버 예외형 시험 1개 건너뜀. 새 로고의 비로그인 접근, 임의 파일 비공개, 로그인 사용자 입력의 HTML 이스케이프를 포함한다. DB 회귀와 실제 TLS 배포 검증은 #104·#106의 남은 작업과 함께 수행한다.
