# 관제 대상 web-01 수집 결과 (WBS 3.4.2~3.4.4 · 이슈 #11)

작성일 2026-09-21 · 설계 `docs/2026-09-21-web01-수집-설계.md` · 선행 `docs/2026-09-21-수집-파이프라인-결과.md`

관제 대상 서버 web-01 을 내부 서비스망에 붙이고, 에이전트가 등록된 키로만 로그를 보내게 했다.
등록되지 않은 전송은 거부되고 R202 인시던트가 된다.

---

## 1. 구성

```
[web-01 192.168.50.21 · 768MB]
 nginx(JSON 로그) · sshd(auth.log) · 1분 지표 ─▶ Grafana Alloy 1.19.2 (에이전트 키)
            │ tcp 3101 (방화벽: web-01 → 데이터 노드는 이 포트만)
            ▼
[data-01 192.168.60.11 · 2GB]
 수집 관문 3101 ─ 키 · 출발지 확인 → Loki 127.0.0.1:3100 (테넌트 = 노드, 원장)
      └ 거부 → 401 · 본문 버림 → 관문 원장 → R202
 1분 다리 ─ Loki · 관문 원장 → events · node_metrics → 탐지 s1(R202) · n1(R101)
```

| 위치 | 구성 요소 | 실측 메모리 |
|---|---|---|
| web-01 | Grafana Alloy 1.19.2 (버전 고정, 한도 256M) | 실사용 38MB (최고 54MB). `ps` 의 196MB 중 156MB 는 실행 파일 매핑 |
| web-01 | nginx JSON 로그 · 지표 타이머 · rsyslog 반복 축약 끔 | — |
| data-01 | 수집 관문 `opsloop-gate` (한도 64M) | 15MB |
| data-01 | Loki 3.7.8 (루프백 전용, 한도 384M) | 72MB |
| data-01 | 1분 다리 `opsloop-agents` | 실행 중에만 |
| data-01 | PostgreSQL (한도 1G → 768M) | 66MB |
| console-a | 호스트 가드 `opsloop-guard` (서비스망에서 방화벽 외 직접 접속 차단, IPv6 차단) | — |
| Mac | Ansible (ansible-core 2.21) · 제어 노드 | VM 밖 |

web-01 가용 메모리 416MB, 데이터 노드 가용 1.4GB 로 여유가 있다. Mac 스왑은 콘솔 B 를 평소 끈 뒤 5.8GB → 4.5GB.

## 2. 등록 절차 (실제로 한 순서)

```bash
cd infra/ansible
ansible-playbook consoles.yml --limit console-a        # 콘솔 가드 (콘솔 B 는 켤 때 --limit console-b)
export OPSLOOP_ENROLL_TOKEN="$(ssh -F ~/.ssh/config.opsloop data01 sudo /opt/opsloop/app/collector/nodes.py \
    issue web-01 --host opsloop-web-01 --addr 192.168.50.21 --logs nginx,auth,metrics)"
ansible-playbook web01.yml                            # 구성 창 → nginx · 지표 · Alloy → 키 생성 → 자기 등록 → 첫 수신 확인
unset OPSLOOP_ENROLL_TOKEN
ansible-playbook web01.yml                            # 두 번째 실행 changed=0
```

- 에이전트 키는 web-01 이 만들고 해시만 등록한다. Mac 이 본 것은 1시간 · 1회용 등록 토큰뿐이다.
- web-01 은 평소 인터넷에 나가지 못한다. 플레이북이 방화벽의 구성 창(30분 자동 만료)을 열고, 끝나면 닫는다.

## 3. 검증

**첫 수신 확인** (`nodes.py check`, 등록 후 55초에 모두 통과)

| 단계 | 결과 |
|---|---|
| 1 등록 | 키 ff3ab92d, 192.168.50.21 에서 자기 등록 |
| 2 첫 로그 | nginx · auth · metrics 세 로그 도착 |
| 3 형식 변환 | 탐침 요청 1 · SSH 로그인 1 · 지표 2행. 복제 전 호스트명(opsloop-base)으로 남은 옛 auth 줄 460 은 foreign_host 로 걸러짐 |
| 4 규칙 적용 | n1:R101 이 이 노드를 봄 |

**미등록 에이전트 시험** (설계 4장 ①~⑥)

| 시험 | 결과 |
|---|---|
| ① 토큰 없이 전송 | 401 missing |
| ② 임의 키 | 401 unknown |
| ③ 등록 토큰으로 전송 / 쓴 등록 토큰 재사용 | 401 unknown / 401 enroll_used |
| ④ 다른 노드(probe-02)의 키를 web-01 에서 | 401 addr_mismatch |
| ⑤ 폐기된 키 | 401 revoked |
| ⑥ ① 을 10회 | 인시던트 1건. 원장 줄은 (출발지, 사유)별 분당 2줄 이하 |
| 표식 부재 | 거부된 본문에 넣은 표식이 events · Loki · 원장 어디에도 없음 |
| R202 | 거부 후 약 1분에 인시던트 2건 (출발지 web-01 · 방화벽) |

③~⑤ 의 시험 노드는 방화벽(데이터망 192.168.60.1)을 출발지로 썼다. Mac 은 VPN 으로 SSH 만 열려 있어 3101 에 닿지 않는다(설계대로).
시험 노드 probe-01 · probe-02 는 폐기 상태로 남겨 둔다. 시험 인시던트 2건은 콘솔에서 양성 정탐으로 판정한다(판정은 사람이 한다).

**방화벽** (`infra/vmware/scripts/verify.sh`, 25항목 모두 정상)

- web-01 → 데이터 노드 3101 만 통과. DB 5432 · Loki 3100 · 22 · 콘솔 8000 · 22 · IPv6 링크 로컬 · 방화벽 8443 · 관리망 · 인터넷 443 은 모두 실패.
- 데이터 노드 → web-01 80 실패 (단방향). 콘솔 → 3101 · 3100 실패, 콘솔 → 5432 통과 (회귀 없음).

**허니팟 경로에 영향 없음**

- 탐지기 변경(발생원 범위 · 실행 기록 · --quiet) 전후로 운영 DB 사본 두 개에서 v1 · v2 를 처음부터 다시 돌렸다.
  v1 274건 · v2 183건, 인시던트 키 지문(md5)이 **같다**.
- 127.0.0.1 을 제외 목록에 더했지만 기존 cowrie · decoy 행 중 127.0.0.1 출발은 0건이다.
- 5분 적재기(허니팟 경로)는 고치지 않았다.

**시험 코드** 271건 통과 (관문 43 · CLI 44 · 다리 27 · 에이전트 파서 37 · 탐지기 17 · Ansible 파일 31 · 기존 72).

## 4. 설계에서 바꾼 점

- **R101 · R202 는 1분 다리에서 돈다.** 설계안은 R101 을 5분 적재기에 두었다. 그러면 발표장에 인터넷이 없어 S3 가 실패할 때
  web-01 탐지도 보류된다. web-01 경로는 내부(Loki)에서 끝나므로 S3 와 분리했다. 48시간 병행 대조 중인 허니팟 경로도 건드리지 않는다.
- **R101 최소판을 이 이슈에 넣었다** (`detector/rules_node.json` n1: sshd 실패 · 없는 사용자 10분 5회). R102 와 규칙군 정리는 3.5.1 에서 한다.
- **Alloy 메모리 관문**은 실제 사용량(RssAnon)과 가용 메모리로 판정했다. 768MB 로 충분해 1GB 로 올리지 않았다.

## 5. 운영

| 할 일 | 명령 (data-01) |
|---|---|
| 노드 목록 | `sudo /opt/opsloop/app/collector/nodes.py list` |
| 새 노드 등록 토큰 | `sudo .../nodes.py issue <노드> --host <호스트명> --addr <주소> --logs nginx,auth,metrics` |
| 노드 폐기 (즉시 반영) | `sudo .../nodes.py revoke <노드>` |
| 첫 수신 확인 | `sudo .../nodes.py check <노드> --nonce <번호> --wait 600 --kick` |
| 관문 · 다리 로그 | `journalctl -u opsloop-gate` · `journalctl -u opsloop-agents` |
| 관문 원장 | `/var/lib/opsloop/gate/collector-YYYY-MM-DD.jsonl` (거부 · 등록 · 제한), `/var/lib/opsloop/admin/admin-*.jsonl` (발급 · 폐기. 관문이 쓸 수 없는 root 전용 폴더) |

백업: `infra/vmware/scripts/backup-db.sh` 가 DB 덤프와 함께 Loki · 관문 원장을 Mac 의 `~/opsloop-backup/ledger` 로 받는다.
