## WBS 직접 수정값

사용자가 Excel에서 직접 고치기로 한 범위다. 원본 `OpsLoop_WBS_v2.0.xlsx`와 기존 미커밋 수정은 변경하지 않았다. 먼저 사본을 남기고 WBS 번호와 셀을 함께 확인한다. 행을 넣거나 지우지 않는다.

| 셀 · 항목 | 반영할 값 | 조건 |
|---|---|---|
| F71 · 4.1 단위 시험 | 완료 | 결과서 3장 및 13장의 조건·시험 판은 유지 |
| F73 · 4.3 통합 시험 | 완료 | 결과서 5장 및 12.4의 합격·미시험·목표 미달을 일괄 합격으로 바꾸지 않음 |
| F90 · 5.13 테스트 결과서 | #96 병합 전 진행중, 병합 뒤 완료 | 문서 마감 완료를 뜻하며 모든 기능·운영 조건이 합격했다는 뜻은 아님 |
| C75 · 4.5 복원 훈련 작업명 | 백업 복원 훈련 (DB 인스턴스 손실 가정 · 별도 컨테이너 복원 · 역할 목록 · 무결성 · 원장 재적재 대조 · RTO 411초(10/02 재훈련) · 복원 런북) | 기존 ‘새 서버 복원’ 표현과 9/27 수치를 현행 근거에 맞춤 |

종료일(H열)은 실제 완료일과 사용자의 일정 기준으로 입력한다. 4.2·4.4의 기존 수정, 날짜·진척 수식은 임의로 바꾸지 않는다. 저장 후 대시보드·산출물 체크리스트가 F열을 반영하는지 확인한다.

## 발표에서 사용할 기준 문장

- “같은 Mac 안에서 서비스·데이터·관리 세그먼트를 논리적으로 나눴고, AWS 허니팟은 외부 관측 역할로 둡니다.” 물리 호스트 장애를 분리한 구성이라고 설명하지 않는다.
- “10/02 통합 시험에서 지점 보고는 늦은 쪽 기준 35.5초, 콘솔 지점 칸의 DB 반영은 80.9초였습니다.” 두 값을 모두 ‘화면에서 차단 확인까지’라고 부르지 않는다.
- “콘솔 B를 켠 6회 시험에서 DOWN 통계 관측은 5.05~5.92초, 연속 성공 20회를 확인한 시각은 주입 뒤 2.27~2.40초였습니다.” 0.36~0.49초는 연속 성공 구간의 첫 요청 시각이며 완료를 확인한 시각이 아니다.
- “판정 입력 시간은 상세를 이번에 연 때부터 저장 버튼을 누를 때까지입니다. 처음 발견하고 조사한 전체 시간은 아닙니다.” triage 경로는 근거 제시→입력 끝을 단조 시계로 재며 DB에는 두 경로가 섞인다.
- “10/02 전체 복원 재시험 RTO는 411.326초였고, 백업 간격 최댓값 86,401초는 목표 12시간을 넘었습니다.” 복원 합격과 백업 간격 미달을 함께 말한다.
- “10/03 영상에서는 실제 노드 편입, 내부 방화벽 새 연결 차단·해제, 격리 복원 콘솔 사용을 추가 확인했습니다.” 기존 탐지·장애 전환 기록과 같은 연속 회차로 설명하지 않는다.
- “로그인 시도 제한·TLS·데이터 노드 감시와 보존·웹훅 이름 검증은 상시 운영 및 다른 사용자 접속 전에 보강해야 합니다.” 단순 미관 개선과 구분한다.

전체 발표 문답은 저장소 밖 `~/opsloop-work/presentation/qa*.md`에 있다. `qa.md`·`qa-ops.md`·`qa-operator.md`의 예정 표현과 계측 문구를 이번 기준에 맞추고 질문 수는 유지했다. 변경 전 사본은 로컬 `output/docs-final-96/qa-before/`에 남겼다. 발표 자료로 옮길 때 오래된 행 번호보다 결과서 절 제목과 증거 경로를 기준으로 인용한다. 슬라이드 제작은 이 문서 PR 범위 밖이다.
