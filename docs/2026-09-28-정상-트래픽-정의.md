# 정상 트래픽 정의 (WBS 3.7 · 이슈 #49)

작성일 2026-09-28 · 선행 문서 `docs/2026-09-18-웹-디코이-설계.md`, `docs/2026-09-22-탐지-규칙-추가-결과.md`, `docs/2026-09-25-폐루프-2회차.md`, `docs/2026-09-08-판정-기준.md` · 정의 파일 `detector/normal_traffic.json` · 생성기 `detector/normal_traffic.py` · 시험 `detector/test_normal_traffic.py`

허니팟 · 디코이에는 정상 사용자가 없어 재현율만 잴 수 있고, 관제 콘솔 · web-01 에는 실사용이 거의 없어 오탐률의 분모가 없다.
이 문서는 오탐 분모가 될 **정상 사용을 미리 정의**하고, 그것을 실험 DB 사본에 넣는 방법과 걸렸을 때의 판정값을 고정한다.
정의가 오탐 여부를 결정한다. 판정자의 해석이 아니다. 시각은 모두 UTC 다.

---

## 1. 목적

- 정상 사용자가 없는 환경에서 **오탐 분모를 확보**한다. 기획안 7.6 의 '자체 운영 작업 + 명시적으로 생성한 시험 트래픽으로 정상
  사례와 경계 조건을 확보한다' 를 실행하는 것이다.
- 디코이에서 뽑은 규칙(R101 · R102, `detector/rules_w1.json` w2)을 정상이 있는 구간에 리플레이해 걸리는 정상 사용을 세는 것이
  3.8.2(폐루프 3회차)다. 이 문서의 시나리오 표가 그 구간의 입력이자 라벨이다.
- 목표 수치는 없다. 걸린 건수는 시나리오 표가 정하는 설계값이며 결과표에는 분모 · 구간 · 규칙 버전 · 출처와 함께 관측값으로만 적는다.

## 2. 어디에 넣는가 — 실험 DB 사본

정상 트래픽은 **실험 DB 사본(Mac 도커 postgres · 127.0.0.1:55449)에만** 넣는다. 운영 콘솔 · web-01 · 허니팟 · 디코이에는 요청을
보내지 않고, 운영 DB 에는 아무것도 쓰지 않는다. 이유 세 가지다.

| 이유 | 내용 |
|---|---|
| 콘솔 기록은 표식이 없다 | `app/auth.py` INSERT_EVENT 가 provenance `real` · sensor `console` 을 상수로 넣는다. exclusions 도 보지 않아 운영에서는 시험 행을 가를 수 없다 |
| 1분 다리가 전 기간을 다시 본다 | 운영에 넣으면 1분 안에 R101 · R102 · R105 가 평가하고 새 사건 · 콘솔 통보 · rule_quality 오염이 즉시 생긴다. R005 기준선도 console 을 센다 |
| 사건 표에 출처 열이 없다 | incidents 에 provenance 가 없어 rule_quality 뷰로는 정상 시나리오 사건과 실제 유입 사건을 나눌 수 없다. 결과표는 실험 DB 에서 출발지 · 구간으로 따로 집계한다 |

운영 콘솔에서 사람이 실제로 하는 로그인 · 조회는 그대로 `real` 로 남는다. 그것은 '실제 정상 사용 구간' 으로 결과표에 따로 적는다(읽기 전용 조회).
`simulated` provenance 는 스키마에만 있고 파서 · 탐지기 · 뷰 어디도 다루지 않아 쓰지 않는다. 탐지기가 보도록 `real` 로 넣되 실험 DB 라서 가능하다.

## 3. 표식 규약

| 자리 | 값 | 비고 |
|---|---|---|
| `message` | `[정상 시나리오 <id>] …` | 모든 행. `--rollback` 은 이 머리(`^\[정상 시나리오 [A-Z][0-9]{2}\] `) + sensor(console · web-01) + 아래 UA 머리 또는 username 머리가 함께 있는 행만 지운다 |
| `user_agent` | `OpsLoop-Normal49/<id> …` | HTTP 행(console.* · nginx.request). 격리 시험의 UA 표식(`OpsLoop-Authorized-Isolation-Audit-…`) 선례를 따른다 |
| `username` | `normal49.<계정>` | 인증 행(console.login.* · console.logout · sshd.*). 없는 계정 시나리오는 `normal49.opz` |
| `line_hash` | `sha256('normal49\|<id>\|<seq>\|<ts>')` | 구간이 다르면 해시가 달라 겹치지 않는다. 같은 구간 재적용은 ON CONFLICT DO NOTHING 으로 멱등 |
| `provenance` | `real` | 탐지기가 본다. 실험 DB 에서만 |
| `sensor` | `console` · `web-01` | 발생원 |
| `session` | 콘솔 성공 `n49-<id>-<seq>` · sshd `web-01/sshd/<pid>` · nginx 없음 | 콘솔은 토큰 앞 17자, sshd 는 parse_agent 모양 |

출발지는 셋이다. 콘솔 `192.168.70.1`(관리 단말 Mac. 이슈 #43 뒤 HAProxy 가 X-Forwarded-For 를 제 것으로 붙여 실제 클라이언트
주소가 남는다), web-01 sshd `192.168.50.1`(fw ProxyJump. 관리자 전원이 이 주소로 뭉친다), web-01 nginx `192.168.70.1`(관리망 Mac →
web-01:80. nftables forward 의 MGMT accept 로 닿는 유일한 정상 HTTP 출발지). 목적지 포트는 콘솔 8000 · sshd 22 · nginx 80 이다.

시각은 구간 시작을 600초 경계로 올린 뒤 시나리오 오프셋을 더한다. R101 · R102 는 출발지별 **10분 고정창**(`floor(epoch/600)`)으로
세고 신호 사이 1200초 안이면 한 사건으로 묶으므로(aggregation_gap_seconds), 시나리오 하나는 창 하나 안에 끝나고(600초 미만)
시나리오 사이는 **1800초**다. 같은 출발지 · 같은 규칙의 시나리오도 따로 뜬다. 16개 시나리오의 구간 길이는 8시간(28,800초)이다.
구간 시작의 기본값은 실험 DB `max(events.ts) + 1시간` 이라 실데이터 뒤에 붙는다. 구간 안에 표식이 아닌 이벤트가 있으면 넣지 않는다(종료 3).

## 5. 판정값 규칙

| 사건의 원인 | 판정값 | 근거 |
|---|---|---|
| 이 표의 정상 시나리오(정상 사용 · 우리 자신의 운영 행위) | `false_positive` (오탐) | 판정 기준 §2 '우리 자신의 운영 행위를 공격으로 잡았다'. 정의된 정상 행위가 규칙에 걸리면 그것이 오탐이다 |
| 탐지되기를 의도한 시험(격리 시험 · 노드 등록 시험 · 복원 훈련)이 만든 사건 | `benign_positive` (양성 정탐) | 규칙이 겨냥한 것을 정확히 잡았고 행위자에게 악의가 없다. 2회차 R202 · R301 판정과 같다 |

두 값은 rule_quality 에서 다르게 집계된다. 오탐률의 분자는 `false_positive` 만이고 `benign_positive` 는 비조치율에만 든다(판정 기준 §3).
그래서 정상 시나리오를 양성 정탐으로 적으면 오탐률이 구성상 0 이 된다. 이 표의 시나리오는 모두 오탐이다.
실험 DB 에서의 판정은 operator `lab:normal49`, reason 에 시나리오 id 를 적는다(리플레이 담당). 운영 DB 에는 쓰지 않는다.

## 6. 한계

- **오탐 건수는 설계값이다.** 작업자 1명 · 출발지 1개(콘솔 · nginx 192.168.70.1, sshd 192.168.50.1)라 걸리는 건수는 시나리오 표가 정한다.
  '오탐률 x%' 가 아니라 '사전 정의 정상 시나리오 16개 중 임계치별로 걸린 n개' 로 말한다. 표본 수와 생성 조건은 이 문서와 JSON 이 공개한다.
- **web-01 SSH 출발지 뭉침.** ProxyJump 때문에 관리자 전원의 오타가 192.168.50.1 한 창에 쌓인다. S03 이 걸리는 것은 관리자 한 사람의 오타 5회와
  여러 사람의 오타 합 5회를 가르지 못한다는 뜻이다. 이 사건의 차단은 block_exempt(192.168.0.0/16)가 거부하므로 콘솔은 끊기지 않는다.
- **10분 고정창.** 시나리오는 창 안에 들도록 배치했다. 창 경계에 걸친 4 + 4 는 현행 규칙이 잡지 않는다(9/22 문서 1절). 미끄럼 창은 2회차 §6 R001 이관과 함께 다룬다.
- **정상 HTTP 헬스체크는 운영에 없다.** W06 은 기획안의 '헬스체크 요청' 을 정의한 순수 설계값이다. web-01 의 실 HTTP 트래픽은 0 이다.
- **분모가 작다.** 16개 시나리오 · 66행이다. 비율을 쓸 때는 반드시 옆에 분모 · 구간 · 규칙 버전 · 출처를 적는다.
- **디코이 재현율은 여기서 재지 않는다.** 정상 구간은 오탐만 준다. 재현율은 디코이 구간에서 따로 잰다(웹 디코이 설계 §6 4번).

## 7. 생성 · 되돌리기 명령

실험 DB 는 리드가 복원한 컨테이너 `opsloop-lab49`(127.0.0.1:55449)다. 셸에 `DATABASE_URL` 을 두지 않는다. 생성기는 `--db-url` 만 읽고,
호스트가 글자 그대로 `127.0.0.1` 이 아니거나 포트가 55449 가 아니면 종료 2 로 거부한다(시험용 임시 컨테이너만 `--allow-port`).
`--db-url` 에 질의 문자열(`?host=` · `?hostaddr=` · `?port=` · `?service=` …)이나 호스트 둘 이상(`a,b`)이 있어도 종료 2 다 — libpq 는 그것으로
netloc 과 다른 주소에 붙는다. 같은 이유로 `PGHOST` · `PGHOSTADDR` · `PGPORT` · `PGSERVICE` · `PGSERVICEFILE` 환경변수는 지우고 붙는다(psycopg2 는
hostaddr 127.0.0.1 로 고정). 붙은 뒤에는 표식 아닌 이벤트의 마지막 시각이 DB 의 `now()` 로부터 30분 안이면 '지금도 이벤트가 들어오는 DB'(운영으로
보임)로 보고 종료 5 로 물러난다. 실험 DB 사본은 덤프 시각 뒤로 멈춰 있어 이 검사를 지난다. `--allow-port` 와 컨테이너 네트워크 공유로 주소 검사를
지나더라도 운영 DB 에는 쓰지 않기 위한 마지막 방벽이다.

```bash
LAB=postgresql://opsloop:<실험 DB 비밀번호>@127.0.0.1:55449/opsloop

python3 detector/normal_traffic.py --table                        # 이 문서의 4절 표 (DB 없음)
python3 detector/normal_traffic.py --db-url $LAB                  # 계획만 (기본 --dry-run · 읽기 전용 트랜잭션 · 쓰지 않는다)
python3 detector/normal_traffic.py --db-url $LAB --apply          # 넣는다. 트랜잭션 하나 · 사건 키 집계(incidents.incident_key md5) 전후 대조
python3 detector/normal_traffic.py --db-url $LAB --apply --window-start 2026-09-27T09:00:00+00:00   # 구간을 직접 정할 때(600초 경계로 올린다)
python3 detector/normal_traffic.py --db-url $LAB --rollback       # 우리 행만 삭제(message 머리 + sensor + UA/username 머리). incidents 는 지우지 않는다(구간에서 뜬 사건 수를 알려 준다)
```

stdout 에 JSON 한 줄이 나온다. `window_start` · `window_end` 가 리플레이의 `--since` · `--until` 이고, `rows_inserted`(66) ·
`rows_marked_in_window` · `incident_keys_before/after` · `incident_keys_unchanged`(true) 를 결과표 1절에 옮긴다.
종료 코드는 0 정상 · 1 정의 오류 · 2 실험 DB 주소 아님 · 3 구간에 표식 아닌 이벤트 있음(message 가 NULL 인 행도 센다) · 4 사건 키 집계가 변함(되돌림) ·
5 지금도 이벤트가 들어오는 DB(운영으로 보임 · 손대지 않음)이다.

드라이버는 psycopg2(detect.py 와 같다)가 있으면 그것을, 없으면 asyncpg 를 쓴다. 둘 다 없는 Mac 에서는 로컬 `opsloop-api` 이미지(asyncpg 포함)
안에서 실험 DB 컨테이너의 네트워크를 공유해 돌린다. 이미지를 새로 받지 않는다.

```bash
docker run --rm --network container:opsloop-lab49 -v ~/opsloop-repo:/repo:ro --entrypoint python opsloop-api:latest \
  /repo/detector/normal_traffic.py --db-url postgresql://opsloop:<실험 DB 비밀번호>@127.0.0.1:5432/opsloop --allow-port 5432 --apply
```

(컨테이너 안에서는 실험 DB 가 127.0.0.1:5432 로 보인다. `--allow-port 5432` 는 그 경우에만 쓴다. 이 명령은 Mac 에서 `opsloop-lab49` 를 상대로만 쓴다.
data01 에서 `--network container:opsloop-db` 로 바꿔 돌리면 주소 검사는 지나지만, 운영 DB 는 지금도 이벤트가 들어오므로 종료 5 가 막는다.)

## 8. 시험

`python3 detector/test_normal_traffic.py`. DB 없이 정의 파일의 모양 · 규칙 파일과의 일치(세는 수 · 기대 반응 · w2 임계치) · 한 창 안 배치 · 행 만들기(열 · 표식 · 해시 · 출발지) ·
주소 거부(localhost · 운영 주소 · 다른 포트 · 질의 문자열 `?hostaddr=` · 호스트 둘 이상 → 종료 2) · 4절 표와 JSON 의 일치를 본다. 도커와 로컬 `postgres:16-alpine` 이미지가
있으면 127.0.0.1 의 빈 포트에 임시 컨테이너를 띄워 schema.sql · 마이그레이션과 씨앗(디코이 404 · message 가 NULL 인 콘솔 행 · 표식을 흉내 낸 남의 행)을 넣고
dry-run 무쓰기 → 실데이터 구간 거부(NULL message 포함 · 종료 3) → 주소를 돌리는 PG* 환경변수 무시 → 지금도 이벤트가 들어오는 DB 거부(종료 5) → apply 66행 · 표식 ·
사건 키 집계 불변 · 재적용 멱등 → detect.py actor_rate 와 같은 신호 문장으로 임계치 5 · 3 · 8 의 기대 반응(3 · 6 · 0) → psycopg2 가 있으면 detect.py 실제 실행 →
rollback 이 우리 66행만 지우고 남의 행은 남기는지 확인하고 컨테이너를 지운다.
