# web-01 수집 설계 (이슈 #11 · WBS 3.4.2~3.4.4)

작성 2026-09-21 · 브랜치 feat/11-web-01 · 전제: web-01 VM(768MB)과 데이터 노드 2GB 축소는 끝났다(73e2b82).

## 1. 결정 요약

- 에이전트는 Grafana Alloy 1.19.2, 원장은 Loki 3.7.8이다. WBS 3.4.2를 유지한다.
- Loki에는 인증 계층이 없다. 그래서 앞에 수집 관문 `opsloop-gate`(192.168.60.11:3101)를 두고, Loki는 127.0.0.1:3100에만 붙인다.
- 관문은 본문을 읽기 전에 토큰 해시와 출발지를 검사한다. 통과한 본문은 바이트 그대로 Loki에 넘긴다. 테넌트(`X-Scope-OrgID`)는 에이전트가 보낸 값을 버리고, 토큰이 증명한 node_id로 붙인다.
- 에이전트 키는 web-01이 만들고, 해시만 등록한다. 등록은 1시간·1회용 등록 토큰으로 web-01이 스스로 한다(계획 개정 4.1). 관문의 DB 권한은 nodes 네 열 읽기와 등록 함수 실행뿐이다.
- 1분 다리가 Loki와 관문 원장을 events·node_metrics로 옮기고, 자기 탐지 R202만 돌린다. 본 규칙 탐지는 기존 5분 `opsloop-ingest`가 한다.
- 첫 수신 확인은 DB 함수 `node_first_receipt()`가 판정한다. Ansible과 나중의 S-13이 같은 함수를 쓴다.
- 줄 해시는 기존 규칙 `sha1(원문 줄)`을 쓴다. 줄 내용이 유일하도록 nginx에는 `$request_id`, auth에는 µs 시각과 pid, 지표에는 µs 시각과 seq가 들어간다.

## 4. 토큰 · 자기 등록 · R202

| 비밀값 | 형식 | 수명 | 저장 |
|---|---|---|---|
| 등록 토큰 | `olE_` + 32바이트 | 1시간 · 1회용 | `node_enrollments.token_hash` (sha256) |
| 에이전트 키 | `olA_` + 32바이트 | 폐기 전까지 | web-01 `/etc/alloy/opsloop.token` (root:alloy 0640). DB에는 `nodes.token_hash`만 |

**절차**

1. **발급(관리자).** S-13 전까지는 CLI로 한다.
   `export OPSLOOP_ENROLL_TOKEN="$(ssh -F ~/.ssh/config.opsloop data01 sudo /opt/opsloop/app/collector/nodes.py issue web-01 --host opsloop-web-01 --addr 192.168.50.21 --logs nginx,auth,metrics)"`
   - 토큰은 화면에도 셸 이력에도 남지 않는다.
   - nodes 행이 `status=pending`으로 생긴다.
   - `node_enrollments`에 발급 이력이 남는다(`issued_by=$SUDO_USER`).
2. **키 생성.** 플레이북이 web-01에서 `opsloop-agent-key`를 실행한다. 키 파일이 없을 때만 만들고, sha256만 출력한다.
3. **자기 등록.** `opsloop-enroll`이 `POST /opsloop/v1/enroll`로 등록 토큰(Bearer)과 `{node_id, agent_sha256}`를 보낸다. 토큰은 Ansible environment로만 넘기고 `no_log`를 켠다.
4. **관문 처리.** 관문은 `SELECT enroll_node(sha256(토큰), node_id, agent_sha256, 출발지)`만 실행한다.
   - `enroll_node`는 SECURITY DEFINER 함수다. search_path를 고정하고 PUBLIC 실행 권한을 회수한다.
   - 한 트랜잭션에서 행을 잠근 채 만료, 1회용, node_id, 출발지=`nodes.addr`를 확인하고 `nodes.token_hash`를 바꾼다.
   - 같은 키로 재시도하면 `ok`를 돌려준다. 응답이 중간에 사라진 경우에 대비한 것이다.
   - 관문은 캐시를 갱신한 뒤에 200을 준다. 그래서 첫 전송이 401을 받는 경합이 없다.
5. **Alloy 기동.** web-01이 등록 표식(키 지문)을 쓰고 Alloy를 기동한다. 표식과 키가 같으면 플레이북을 다시 돌려도 등록을 건너뛴다.
6. **폐기.** `nodes.py revoke web-01`로 status를 revoked로 바꾼다(해시는 남긴다). 관문에 HUP을 보내 즉시 반영한다. 키를 바꿀 때는 새 등록 토큰으로 2~4를 다시 한다.

결과적으로 에이전트 키는 web-01 밖으로 나가지 않는다. Mac이 보는 것은 1회용 등록 토큰과 키 해시뿐이다.

**관문 검사 순서** (모두 본문을 읽기 전에 한다)

1. 경로가 push나 enroll이 아니면 404를 준다. 사유는 `path`다.
2. 캐시(15초 주기, HUP이 오면 즉시 갱신)가 60초보다 오래됐으면 503을 준다. 거부로 치지 않으며, Alloy가 재시도한다.
3. Authorization 헤더가 없으면 401 `missing`.
4. 해시가 없으면 401 `unknown`(등록 토큰을 push에 쓴 경우 포함), 폐기됐으면 401 `revoked`, active가 아니면 401 `inactive`.
5. 출발지가 `nodes.addr`와 다르면 401 `addr_mismatch`.
6. 등록 노드 자신의 문제는 R202가 아니다. 길이 없음 411, 4MiB 초과 413, 노드별 하루 200MiB 초과 429로 답하고 `collector.agent.throttled`로만 남긴다.
7. 통과하면 테넌트를 덮어쓰고 Loki로 넘긴다. Loki에 닿지 않으면 503을 준다.

401을 줄 때는 연결을 닫는다. Alloy는 429를 뺀 4xx를 재시도하지 않으므로, 거부된 묶음은 수집되지 않는다.

**거부 원장 → R202**

- 줄 예: `{"ts":"2026-10-01T05:12:03.481220+00:00","boot":"b7c1e2","seq":17,"eventid":"collector.agent.rejected","src_ip":"192.168.50.21","dst_port":3101,"path":"/loki/api/v1/push","reason":"unknown","count":1,"distinct_fp":1,"fps":["3f9a1c0e"],"ua":"Alloy/v1.19.2"}`
- 묶음 키는 (출발지, 사유)다. 60초 창의 첫 건은 바로 쓰고, 나머지는 창이 끝날 때 한 줄로 합친다.
  - 3101에 닿는 출발지는 방화벽이 제한한다.
  - 그래서 임의 키를 쏟아부어도 줄 수는 분당 2 × 사유 수를 넘지 않는다.
  - 토큰 원문은 적지 않는다.
- 다리는 이 줄을 events에 넣는다. `sensor='collector'`로 두고, 사유는 `input='reason=… count=… fps=…'`에 담는다.
- `detector/rules_self.json`(버전 s1): R202 '미등록 에이전트 접속'을 둔다.
  - 조건: high, event_match, `eventid_like '%.agent.rejected'`, sensors `collector`·`puller`, 통합 창 900초.
  - 탐지기 코드는 바꾸지 않는다.
  - 폐루프 버전 v1·v2와 섞이지 않는다.
- 거부에서 인시던트까지 약 80초 이내다. 기존 NOTIFY 트리거가 콘솔에 올린다. Teams 알림은 3.6.7에서 붙인다.
- 방화벽에서 이미 막힌 시도는 관문까지 오지 않으므로 R202가 아니다. `fw-forward-drop` 기록으로만 남는다.

**시험**

| # | 방법 | 기대 |
|---|---|---|
| ① | web-01에서 토큰 없이 JSON push. 본문에 표식 문자열을 넣는다 | 401. 표식이 Loki와 events 어디에도 없음. R202 (actor 192.168.50.21) |
| ② | 임의 `olA_` 키로 push | 401 unknown |
| ③ | 등록 토큰으로 push / 이미 쓴 등록 토큰으로 재등록 | 401 unknown / 401 enroll_used |
| ④ | 시험 노드 probe-01(addr=Mac)을 Mac에서 등록한 뒤, 그 키로 web-01에서 push | 401 addr_mismatch |
| ⑤ | probe-01을 폐기한 뒤 Mac에서 push | 401 revoked. R202 (actor 192.168.70.1) |
| ⑥ | ①을 10회 반복 | 인시던트 1건, 원장 줄 분당 2개 이하 |

시험으로 생긴 인시던트는 양성 정탐(benign_positive)으로 판정한다.

## 5. 원장 · 줄 해시 · events 변환

**원장**

- web-01의 원장은 Loki 테넌트 `web-01`이다. 보존 기간을 두지 않는다. 두 번째 사본은 web-01의 원본 파일이다(nginx 14일, auth 약 4주 회전).
- 관문 원장은 `/var/lib/opsloop/gate/collector-YYYY-MM-DD.jsonl`, CLI 관리 기록은 `admin-YYYY-MM-DD.jsonl`이다. 둘 다 추가만 한다.
- `backup-db.sh`에 한 줄을 더해, `/var/lib/opsloop/{loki,gate}`를 Mac의 `~/opsloop-backup/ledger`로 `rsync -a` 받는다.

**줄 해시**

`line_hash = sha1(Loki가 돌려준 원문 줄의 UTF-8)`이다. 기존 파서와 같은 규칙이다. Loki 시각은 해시에 넣지 않는다. 그래서 Alloy가 같은 줄을 다시 보내도 events에는 한 번만 들어간다.

**다리** (`collector/pull_loki.py`, 1분)

1. logs가 있는 active·revoked 노드마다 테넌트별로 `query_range {job=~".+"}`를 부른다. forward 방향, limit 5000이다.
2. 조회 창은 평소 [워터마크−5분, 지금−10초]다. 15회에 한 번은 워터마크−100분부터 본다. 100분은 Alloy 재시도 한계(20회, 약 58분)에 깊은 조회 주기(15분)와 여유를 더한 값이다 (구현 검토에서 75분 → 100분).
3. 5000건이 차면 마지막 시각부터 이어 읽는다. 커밋한 뒤에만 워터마크를 올린다. 신규 건수는 `RETURNING`으로 센다.
4. nodes.logs에 없는 job은 `undeclared`로 센다. 줄 속 호스트명이 `nodes.hostname`과 다르면 `foreign_host`로 세고 적재하지 않는다. 기본 VM 시절의 auth.log 줄과 호스트 위장이 여기서 걸러진다.
5. 지표 seq가 건너뛰면 `seq_gaps`로 센다. Alloy가 묶음을 버린 구간을 부분적으로 드러내는 장치다.
6. 관문 원장과 관리 원장의 새 줄을 적재한다(파일마다 inode와 오프셋을 기억한다).
7. `nodes.receipt`, `first_loaded_at`, `last_seen_at`을 갱신한다. 이어서 `detect.py --rules detector/rules_self.json --quiet`를 돈다. Loki가 응답하지 않아도 6·7은 진행한다.

**형식 변환** (`parser/parse_agent.py`)

순수 함수로 만들고, web-02도 같이 쓴다.

| job | 결과 | 주요 필드 |
|---|---|---|
| nginx | `nginx.request` (events) | ts=msec, src_ip·port, dst_port, http_method, http_status, url(2048), user_agent(512), message=원문 |
| auth | `sshd.login.failed` · `sshd.login.success` · `sshd.login.invalid_user` (events) | 머리: RFC3339 µs 시각 · 호스트 · `sshd(-session\|-auth)?[pid]`. session=`web-01/sshd/<pid>`, protocol ssh, dst_port 22 |
| metrics | node_metrics 표 | ts, seq, cpu_pct, mem_used_pct, mem_avail_mb, swap_used_pct, disk_root_pct, load1, nginx·sshd 활성 |
| collector | `collector.*` (events, sensor=collector) | 4장 참조 |

- sensor는 node_id다. sessions 재집계는 하지 않는다. R002는 보호 자산에 적용하지 않는다.
- `invalid_user`는 `%.login.failed`에 걸리지 않게 이름을 따로 두었다. 이중 집계를 막기 위해서다.
- 그 밖의 auth 줄은 `unmatched`로만 센다. 원문은 Loki에 남으므로, 파서를 늘리면 다시 파생할 수 있다.
- `127.0.0.1`을 `parser/exclusions.txt`에 더한다. 첫 수신 탐침 줄이 fixture로 분류된다.
- 재생성은 `pull_loki.py --node web-01 --since <시각>`으로 한다. 두 번째로 실행했을 때 신규는 0건이어야 한다.

**스키마 추가** (`infra/schema.sql`, 멱등. 운영 DB에는 `psql -f`로 적용한다)

- `nodes`에 열을 더한다: addr, logs, agent_fp, first_loaded_at, last_loaded_at, receipt jsonb. `registered_at`의 NOT NULL과 기본값을 뗀다. status에 `pending`을 추가한다. token_hash에 부분 유일 색인을 둔다.
- 새 표: `node_enrollments`, `node_metrics`, `detector_runs`(rule_version, since, until, started_at, finished_at).
- 새 함수: `enroll_node(text,text,text,inet)`, `node_first_receipt(text,text)`.
- 역할 `opsloop_gate`에는 두 권한만 준다: `GRANT SELECT (node_id, token_hash, status, addr) ON nodes`, `GRANT EXECUTE ON FUNCTION enroll_node`.

**탐지 입력** (`detect.py`, `opsloop-ingest` 변경)

- `range_clause`에 발생원 조건을 추가한다.
  - `baseline_deviation`(R005)은 `params.sensors`가 없으면 cowrie·decoy·console로 한정한다. web-01·collector 이벤트가 v1·v2 기준선에 섞이지 않게 하려는 것이다.
  - event_match와 actor_rate는 `params.sensors`가 있을 때만 거른다.
- 검증: 복원 시험 DB에 web-01 이벤트를 넣는다. 변경 전과 후의 v1·v2 인시던트 키 집합 md5가 같아야 한다. 기준값은 265·6e14d1f1…, 22·c6b022b2…이다.
- `run()`이 끝나면 `detector_runs`를 기록한다.
- `opsloop-ingest`
  - 규칙 세트를 `OPSLOOP_RULESETS`로 받는다. 기본값은 `detector/rules.json`이다.
  - S3 가져오기가 네트워크 오류로 실패하면 새 조각 적재만 건너뛰고 탐지는 한다.
  - 구멍은 `detect.hold` 파일로 회차 사이에 유지한다.
  - 48시간 병행 대조가 끝난 뒤 적용한다.
- R101(`%.login.failed`)과 R102(404)는 3.5.1에서 만든다. `%.login.failed`는 cowrie 이벤트도 잡으므로 `params.sensors`로 범위를 정해야 한다.


- **3100 삭제.** Loki는 루프백에만 붙는다. 콘솔은 원문을 `events.message`에서 본다.
- **데이터 → 인터넷 22 삭제.** 옛 'AWS web-01에서 가져오기' 경로다.
- **서비스 → 인터넷은 콘솔로 한정한다.** web-01은 플레이북이 여는 구성 창에서만 인터넷에 나간다. 여는 명령은 `nft add element inet filter provision { 192.168.50.21 timeout 30m }`이고, 끝나면 원소를 지운다. 지우지 못해도 30분 뒤 저절로 빠진다.
- **기록 규칙 순서를 바꾼다.** nftables는 문장을 왼쪽부터 평가한다. 그래서 지금 순서로는 거부 패킷이 전부 기록된다.

**콘솔 A·B 호스트 가드** (전용 oneshot 단위 `opsloop-guard.service`. `flush ruleset`을 쓰지 않는다)

```
table inet console_guard
delete table inet console_guard
table inet console_guard {
  chain pre {
    type filter hook prerouting priority -150; policy accept;
    iifname "lo" accept
    ip saddr 192.168.50.1 accept
    ip saddr 192.168.50.0/24 drop
    ip6 saddr fe80::/10 meta l4proto != ipv6-icmp drop
  }
}
```

가드가 필요한 이유는 다음과 같다.

- web-01과 콘솔은 같은 L2에 있어서, 둘 사이 통신은 내부 방화벽을 지나지 않는다.
- 콘솔은 8000번 포트를 모든 주소에 게시한다.
- docker가 게시한 포트는 DNAT(-100)를 거쳐 FORWARD로 흐르므로 INPUT 체인으로는 막을 수 없다.

그래서 DNAT보다 앞(-150)에서 HAProxy(192.168.50.1)가 아닌 서비스망 출발 패킷을 버린다. 기본 `nftables.service`는 멈출 때 `flush ruleset`을 실행해 docker 규칙까지 지우므로 쓰지 않는다.

## 7. 첫 수신 확인

`node_first_receipt(node, nonce)`는 (단계, 통과, 설명) 네 행을 돌려준다. 앞 단계가 실패하면 뒤 단계는 '대기'로 표시된다.

`sudo nodes.py check web-01 --nonce N --wait 600 --kick`은 이 함수를 5초마다 조회한다. 종료 코드는 처음 실패한 단계의 번호다. Ansible 마지막 작업이 data-01에 위임해 실행한다.

| 단계 | 통과 조건 | 실패 단서 |
|---|---|---|
| 1 등록 | status=active, token_hash 있음, 등록 토큰이 만료 전에 쓰임, used_from=addr | 만료·재사용이면 다시 발급 |
| 2 첫 로그 | 선언한 로그마다 `receipt[log].first_line_at` 있음. 다리가 Loki 테넌트에서 실제 줄을 본 시각이다 | Alloy 저널, 관문 원장의 401 사유, 방화벽 3101 |
| 3 형식 변환 | nonce가 든 `nginx.request`(204) 1건, `sshd.login.success` 1건 이상, node_metrics 1행 이상, 호스트가 맞는 줄의 malformed·repeated 0. foreign_host는 건수만 보인다 | log_format, rsyslog 반복 축약, 호스트명 |
| 4 규칙 적용 | `started_at > first_loaded_at`인 `detector_runs`가 있고, 그 규칙 버전에 이 노드 eventid와 맞는 활성 규칙이 있음(eventid · eventid_like · eventids, sensors가 있으면 노드 포함). 맞는 규칙 ID를 보인다 | `detect.hold`(S3 구멍), '이 노드를 보는 규칙 없음'(3.5.1 확인) |

입력 줄은 플레이북이 만든다.

- auth: `meta: reset_connection` 뒤에 작업 하나를 돌려 새 SSH 로그인 줄을 남긴다.
- nginx: web-01 안에서 `curl http://127.0.0.1/opsloop-first-receipt/<nonce>`를 보낸다(204).
- metrics: 1분 안에 한 줄이 생긴다.

`--kick`은 3단계를 통과하면 `systemctl start opsloop-ingest`로 본 탐지를 한 번 당긴다. R202는 web-01 이벤트를 보지 않으므로 4단계를 통과시키지 않는다. 4단계는 3.5.1의 R101·R102가 먼저 있어야 통과한다. WBS 순서(9/26~9/28)도 3.5.1이 먼저다.

## 11. 위험

- **Alloy 메모리.** 공식 추정은 로그 1MiB/s당 120MiB다. 그런데 이슈 #3953에서는 300MiB~1GiB를 썼다는 보고가 있다. 10단계 관문을 넘지 못하면 web-01을 1GB로 올리고 콘솔 B를 평소 꺼 둔다.
- **Loki 메모리.** 비공식 사례로 300~500MiB다. GOMEMLIMIT, 컨테이너 한도, 결과 캐시 끔을 적용한다. 한도에 걸려 재시작하면 관문이 503을 주고 Alloy가 재시도한다.
- **긴 중단 시 유실.** 관문이나 Loki가 약 58분(재시도 한계)보다 오래 멈추면 그 묶음은 버려진다. 알아챌 수단은 지표 seq 공백뿐이다. 복구는 web-01 원본 파일에서 위치 파일을 지우고 다시 보내는 것이다. '구멍이 있으면 탐지 보류'는 이 경로에 적용되지 않는다.
- **평문 전송.** 관문은 평문 HTTP라 에이전트 키가 암호화 없이 지난다. 출발지 결속과 즉시 폐기로 줄이고, 여유가 있으면 자체 CA로 TLS를 붙인다.
- **같은 L2의 한계.** 가드는 직접 접속만 막고 ARP 위장은 막지 못한다. 관제 대상 전용 세그먼트는 범위 밖이다.
- **장악된 web-01.** 자기 이름으로 위조한 로그를 보낼 수 있다. 그래서 3.9 자동 차단은 web-01 증거만으로 집행하지 않는다.
- **R101 범위.** `%.login.failed`는 cowrie 이벤트도 잡는다. 3.5.1에서 sensors로 범위를 정한다.
- **rsyslog 반복 축약.** 켜져 있으면 과소 집계된다(버그 1837076). 플레이북이 끄고, 3단계가 repeated 건수로 드러낸다.
- **Loki 항목 시각.** 다리는 Loki 항목 시각이 Alloy가 읽은 시각이라고 가정한다. 첫날 확인한다. 스트림 최신 항목보다 1시간 넘게 오래된 항목은 Loki가 거부한다.
- **허니팟 경로에 닿는 변경.** opsloop-ingest와 detect.py 변경은 48시간 병행 대조가 끝난 뒤 적용하고, 지문을 다시 대조한다.
- **보안 업데이트.** web-01은 구성 창 밖에서는 업데이트를 받지 못한다. 갱신 절차를 런북에 적는다.
- **nginx 회전 순간.** 로그 파일이 회전되는 순간 몇 줄이 빠질 수 있다.
- **Loki rsync 사본.** 쓰는 중에 받으므로 마지막 파일이 어긋날 수 있고, 다음 회차가 덮는다.
