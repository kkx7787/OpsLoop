## KPT

### Keep

- 실패를 넣고 원인·수정·재측정을 연결한 운영 훈련을 유지한다. 성공 화면만 남기지 않고 실패 회차도 보존한다.
- 실험 DB, 제한된 역할, 읽기 전용 확인, 명시적 사람 승인을 유지한다. 이번 검증도 합성 자료와 격리 DB로 했다.
- 증거를 실행 코드·조건·날짜와 묶는다. 과거 측정이 어느 버전의 결과인지 보존한다.
- 추천과 결정, 차단 요청과 실제 적용, 판정 이력과 현재 판정을 분리한 설계를 유지한다.
- 사용자가 만든 디자인과 최종 산출물은 존중한다. 종료 후 코드 개선 때문에 발표 기록을 새 성과로 다시 쓰지 않는다.

### Problem

- 정상 흐름 시험에 비해 **다른 진입점·첫 요청·재판정·동시 변경·날짜 경계**가 부족했다. 이번 M2·M3·L24와 CTI 시험이 구체적인 예다.
- PR 개수와 통과 시험 수를 검토 품질의 대용으로 삼기 쉬웠다. 어떤 위험을 반증하는 시험인지 연결이 약했다.
- 비운영 조건과 실제 장애, 설계 선택과 버그, 정적 추론과 실행 증거가 회고에서 섞였다.
- 배포했다고 기록한 버전과 실제 노드의 실행 버전을 구분하지 못한 사례가 기존 회고에 있다. 예비 노드까지 포함한 배포 확인 기준이 필요하다.
- 반복해서 ‘마지막 검토’나 ‘더 수정할 것 없음’을 선언했다. 확인 범위와 남은 항목을 명시하는 종료 기준이 더 적절하다.
- 이슈 3건보다 넓은 9건을 한 브랜치에 담고 저장소 명명 규칙도 놓쳤다. 이슈·변경 범위·검증 결과를 먼저 일치시켜야 한다.

## 종료 판단과 후속 우선순위

이번 회차는 **1차 9건의 범위를 분리하고 정합성 보완까지 변경 영향 시험을 마친 상태**다. 병합·운영 배포는 별개이며, 후속 검증 항목이 없다고 선언하지 않는다.

남은 항목은 [#130](https://github.com/kkx7787/OpsLoop/issues/130)에서 추적한다. L16의 R006 흡수 동등성은 누락 표본을 확정한 뒤 새 규칙 버전과 재적용 평가가 필요해 현재 규칙의 의미를 임의 변경하지 않았다. L4·L28·L31·L51은 실제 동시성 또는 인프라 조건을 갖춘 별도 시험이 필요하다. 세션 철회·수동 실행 잠금·공개 설정 정리도 서비스 재개 전에 점검한다. 단순 미관 개선과 서비스 재개 전 검증을 같은 우선순위로 취급하지 않는다.

새 기능, 담당자 업무 체계 확대, 모델 자동 학습, UI 전면 개편은 이번 종료 보완에 넣지 않는다. 정책을 바꾸어야 해결되는 항목을 코드만 바꿔 ‘해결’로 표시하지 않는다.

1차 수정의 확인 범위는 [1차 시험 기록](evidence/2026-10-17-postproject-review/README.md), 현재 추가 변경은 [정합성 시험 기록](evidence/2026-10-17-data-integrity/README.md)에 고정한다. 과거 장애 전환 시간·복원 시간·AI 수치는 각각의 원래 증거로 남긴다.
